Permission rules

        
Rules are checked before the permission mode. Deny always wins, then Ask, then Allow. Plan mode still refuses edits whatever the rules say. A command pattern like npm test* matches what Bunny is about to run; a path pattern like secrets/** matches the files Bunny's own tools read or edit (not what a command does). Simple wildcards only: * and **.

        
Only from Bunny's window. In the desktop app, the rules, the permission mode, connectors, schedules, hooks, skills, sign-ins, providers and the other settings that decide what Bunny may do change only from this window. Anything else on this computer that tries gets "Change this in Bunny's window.", which means the request was refused and nothing was changed.

        
A guard rail, not a sandbox. Command rules read the command Bunny is about to run; they do not cover custom tools, MCP or local connectors, computer-use typing, the browser tools or schedules, and a wrapper such as cmd /c or powershell -Command can hide what it runs (Bunny asks about those when you have a Deny or Ask rule).
