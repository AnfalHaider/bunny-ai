## Local models, run by Bunny

- **Bunny can now run AI models on this PC itself, with no other app needed.** On the **Providers** page, under **Available: on this PC**, choose **Set up Bunny local**. Bunny downloads its runner program from GitHub (llama.cpp), checks it against a fixed fingerprint, and runs it only on this PC.
- **Two models to start:** Qwen3 4B and Granite 4.1 3B, downloaded from Hugging Face. Each download is checked by fingerprint. Downloads can be paused and picked up where they stopped.
- **Fit badges:** each model says whether it fits this PC's memory before you download it.
- **Graphics card:** on NVIDIA cards Bunny uses the graphics card. Other PCs run on the processor, which is slower but works everywhere.
- **Starts when you need it:** the first message starts the model ("Starting your local model…"), and it stops by itself after a set idle time. You can also stop it from the card.
- **Stays on this PC:** the runner listens only on this PC and needs a key that Bunny alone holds. Phones and other signed-in devices can't set up, start or manage local models.
- **Smart mode with a local model:** when the chat's model is a Bunny local model and no checking model is chosen, Smart asks before risky steps, because a small local model is a weak check. Choose a checking model in **Settings › Permissions** to let Smart decide.

## Your own model files

- **Add a model from this PC…:** pick any .gguf model file, for example one you downloaded with LM Studio. Bunny uses the file where it is and never copies, changes or deletes it.
- **The add card shows what you're adding:** the file's facts, whether it may not fit in memory, and its chat format. A format Bunny doesn't recognise is shown as "Unknown chat format", with the template there to read. **Don't add** is the main button.
- **Tools are off for models you add.** You can switch them on for each model in the window.
- **Bunny refuses files it can't run safely:** files that aren't GGUF, incomplete files, split files, vision helper files, links and files on network drives.

## Model folders and the download place

- **Model folders:** add folders, and Bunny lists the model files in them, three folders deep, counting the one you add. LM Studio's models folder is found automatically and listed first. Each folder has **Refresh** and **Remove**. Bunny only reads these folders.
- **Choose where downloads go:** **Change…** picks the folder Bunny saves its models in. Bunny saves into a "Bunny models" folder inside it, locked to your account. When you change the place, Bunny offers to **move** your models there, checking each copy before deleting the old one, or to leave them where they are.
- A model folder can't be a network drive, a whole drive, a system folder, your profile folder, or Bunny's own data. The download place also can't be a USB drive, Downloads, Desktop, a project folder, or a folder that overlaps your model folders.
- **Remove…**, then **Remove everything**, deletes the runner and the models Bunny downloaded, wherever they are. It never touches the files and folders you added. It tells you about any model it left behind.

## Web search without a key

- With no Brave key, web searches try DuckDuckGo, then Bing, then Wikipedia. Bunny checks that results match the question before using them.

## Claude Code sign-in

- When the Claude Code sign-in page gives you a code to copy, Bunny now has a box to paste it into.

## Known limits

- Local models are tested on the processor and on one NVIDIA card. Intel graphics runs on the processor for now.
- Mapped network drives are refused by drive type; this wasn't tested on a PC with a real network share.

## Updating

Copies update on their own (**Restart to update**, or check for updates in **Settings → About**).
