## Plugins, skills and connectors

- A plugin brings its skills, commands and agents; commands and agents become skills you run from the **/** menu. A plugin can be updated from its card, and switched on or off as a whole.
- Anything I add on my own (a plugin, a skill I write, a connector with an address) arrives switched **off** in every permission mode, and its card shows the whole text before you switch it on. On an update, new or changed skills arrive off and are listed.
- A connector's read-only tools run without asking only while you trust its read-only labels, and only for the tools you saw when you trusted it; a new tool or a changed label takes that trust away.
- Keys for local connectors are kept in the Windows secret store, never in a settings file.
- A tool that returns a picture shows it to a model that can see. Uninstalling one plugin never removes a connector another plugin still uses.

## Folders

- Skills, connectors and plugins can be limited to folders (**Customize → Only in a folder…**). A chat only offers the ones for everywhere or for its own folder.

## Install a tool from GitHub

- I can install a Node.js tool from a public GitHub repository as a local connector, only after a card you answer, in Ask and Auto alike; Plan mode refuses it. The card names the exact commit, the command it runs, and says that this runs code from the internet. Install scripts never run, the repository's own npm settings are ignored, and nothing is installed if the repository changes after you said yes.

## Layout

- **Settings → Code**: the permission rules block has its inner padding back, and the All folders / One folder switch sits inside its card. Settings and Customize were checked for content on borders and overflow at desktop and phone widths, in both themes.

## Quick ask

- **Add a file…**: attach a picture (up to 3 MB), a PDF (up to 8 MB) or a text file (up to 128 KB). A file that looks like it holds a key or a password, a network path, or a file whose contents don't match its type is refused.

## Models and replies

- The model picker has a **Thinking** level for providers that support it; other providers don't show it, and Default sends nothing.
- If a model fails partway through an answer, the words it already wrote are kept, and the model that takes over carries on from them.
- Some models refuse two messages from the same side in a row; I now join them before sending. Saved chats are unchanged.
- A Code chat carries its open task list into your next message: if your message is about that work, I carry on from the first open step; otherwise I follow your new message.
- If a picture job (copying or comparing how a page looks) goes to a model you picked by hand that cannot look at pictures, I say so once before I start. Auto picks a model that can look.
- A permission or question card waits for your answer; it is never denied on its own, and I nudge you after a while.

## Browser panel (desktop app)

- Each tab is now a real browser view, with cookies kept apart from my own. Pop-ups open as tabs, downloads are blocked, and my own address is never opened there.
- I can inspect a page (its HTML, styles, network requests and fonts) and save a full copy of it into the chat's folder.

## Safer by default

- Updates install only when the release has a published checksum.
- Signing in to a connector checks where each address really points and refuses addresses on your own computer or network.
- No download can reach my own server, in any spelling of its address.
- Very large requests are refused before they are read, and only one over 1 MB is read at a time.

## Also

- Clearer messages when a search stops, when no provider has a model left, and fewer "please run this yourself" requests slipping through.
- Picker labels and the model-switch line are easier to read in the light theme.
