One required fix, in the dangerous direction. commandParts follows POSIX quoting, but run_command is PowerShell: a backslash is not an escape and a backtick is. Probe on a scratch checkout of 791dc98 with the one allow rule npm test*: the command npm test then a double-quoted string ending in a backslash, then a semicolon, then Remove-Item -Recurse foo comes back as allow, so PowerShell runs the Remove-Item with no question. The same shape hides a command from a deny rule (Remove-Item* deny: no match), and so does a backtick-escaped quote. Fix: parse quotes the PowerShell way (backtick escapes, a doubled quote is a literal, backslash is plain) and, for deny and ask, also test a quote-blind split on ; & | and newlines (matching more is the safe side); for allow require every quote-blind part to be covered too, so doubt becomes a question. Tests with these exact strings. Everything else reads right: Plan is checked before the rules at both call sites and wins; ask always asks in every mode; allow only skips an edit or run question, never send or build; deny stops the call with a message; canon() resolves links and dotdot for path rules; listings and search skip denied paths; start_process is covered; rule API validates and caps. Unit tests permission-rules, permission-rules-app, plan-mode, permission-modes: 38 pass, 0 fail. e2e not run by me. Not blocking, but state them: glob command rules are a guard rail against the model's mistakes, not a sandbox (git -C . push, cmd /c, powershell -Command, aliases like ri and del, iex all slip past a git push* or Remove-Item* deny); path rules do not see what a command does (the screen says so); custom tools, create_tool scripts, MCP and local connectors, computer-use typing, browser tools and schedules are not covered, so say that on the rules screen. For W3-3: keep the order Plan, deny, then ask (a rule ask, the W3-3 asks for create_tool, schedule that may change things and local connector, and every email send), then allow; an allow rule must never skip a W3-3 or send question.
