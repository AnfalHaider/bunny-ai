# W4-13b: request parameters for thinking / reasoning, per provider

Researcher, checked 2026-11-17. Sources are each provider's own docs (links per row). Pages were read through a summarising fetch tool, so re-read the cited page before hard-coding a value. UNKNOWN means I could not confirm it. Nothing was tested with a key.

## What Bunny does today

- Every provider is called at `${baseUrl}/chat/completions` (`src/server/chat.js:337`), the OpenAI shape, even Anthropic (`catalog.js:67-77`). So what matters is each provider's **OpenAI-compatible** form, not its native one.
- Only OpenRouter gets a reasoning field: `{ reasoning: { effort } }`, sent for low/high/max and skipped at medium (`src/server/app.js:2719-2721`, `max` is sent as `high`). It is tied to the chat's "Effort" setting. Every other provider gets nothing.
- Thinking text in replies is read from `delta.reasoning_content` or `delta.reasoning` (`chat.js:406-408`). That covers DeepSeek, Kimi, Z.ai, Vercel and Groq `parsed`; Anthropic's compat layer returns **no** thinking text (below).

## Findings that change the design

1. **No single field works everywhere.** The names in use: `reasoning_effort` (OpenAI, Google, Groq, Cerebras, Mistral, DeepSeek, xAI, Kimi, Fireworks, Together, Vercel alias), `reasoning: {effort}` (OpenRouter, Vercel), `thinking: {type}` (DeepSeek, Z.ai, Anthropic, Fireworks), `enable_thinking` and `thinking_budget` (DashScope, SiliconFlow), `think` (Ollama native), `reasoning: {enabled:false}` (Together).
2. **The level lists differ by model, not only by provider**, so a level picker has to be populated per model. Only OpenRouter (`reasoning.supported_efforts`, `default_effort`, `mandatory` in `GET /models`) and Vercel (catalog discovery page) publish that in their model list. For everyone else it comes from docs; a small table in the catalog (provider, model id pattern, allowed values, can-turn-off) is the realistic source, with a "default only" fallback for unknown models.
3. **Some models cannot be turned off:** xAI Grok, Kimi K3 and K3.1 Pro, Z.ai GLM-5.3 and 5.3-Flash, Opus 5.5, GPT-OSS on Groq/Cerebras, Muse Spark Open, Gemini 3 and 4 and 2.5 Pro, Mistral Large 4, DashScope thinking-only models. An "Off" choice must be hidden or disabled for these.
4. **Anthropic through the OpenAI-compatible endpoint is the weak spot:** `reasoning_effort` is ignored, adaptive returns 400, `budget_tokens` has no effect on Claude 4.7 and newer, and **no thinking text is returned**. Real control of effort (`output_config.effort`) and thinking text needs the native `/v1/messages` API. Decision for the owner/Tech Lead: keep compat (thinking just "on by default", no level), or add a native Anthropic path.
5. **Unsupported values:** only some providers say what happens. 400 errors are documented for OpenAI (`none` on GPT-6 Astra), Anthropic (listed above), Mistral Large 4, Groq (`raw` with tools), Fireworks (both fields), DashScope (non-streaming `enable_thinking` on two Qwen3.5 models). OpenRouter and Together and DeepSeek remap values instead of rejecting. Cerebras, xAI, Kimi, Z.ai, Ollama: not stated or ignored. So a safe client must (a) send only values from its table for that model, and (b) on a 400 whose text names the reasoning field, retry once without it.
6. **Today's 4-step Effort setting is not a thinking level.** `app.js:2719` maps Effort low/medium/high/max onto OpenRouter only, and also changes token and tool-round limits. A "Thinking" picker should be a separate setting from Effort, or the two must be mapped explicitly.
7. **Reasoning text comes back in different fields:** `reasoning_content` (DeepSeek, Kimi, Z.ai), `reasoning` (OpenRouter, Vercel, Groq parsed, Cerebras parsed), inside `content` in `<think>` (some Fireworks, Groq raw), `message.thinking` (Ollama native), none (Anthropic compat). `chat.js:408` reads the first two. `reasoning_format: parsed` (Groq, Cerebras) is needed to get a separate field.
8. **Billing note:** reasoning tokens count against the output limit and are billed even when hidden (`exclude`, `hidden`). Raising the level without raising `max_tokens` can leave an empty visible reply (OpenRouter, Anthropic, Together state this); Bunny already retries once with more room (`chat.js:127-133`).

## Suggested minimal build

A table in `src/providers/` such as `thinkingControls = [{ provider, match, field, body(level), levels, canOff, default }]`, for the rows above marked with a field. Start with the providers where the field and values are confirmed: OpenAI, Google, OpenRouter, Groq, Cerebras, Mistral, DeepSeek, xAI, Kimi, Z.ai, DashScope. Leave NVIDIA, ModelScope, Gitee, SiliconFlow (effort), Ollama (OpenAI endpoint), Copilot and OpenCode with no picker until someone confirms them with a key.
