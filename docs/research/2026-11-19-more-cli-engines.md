# CLI-ENGINES: other agent CLIs that could pass Security's bar

Researcher, 2026-11-19. Official repos and docs only, read through a summarising fetch tool and the GitHub API; nothing installed or run. Where a page did not say, the cell says UNKNOWN. Re-read the cited page before building on a number.
Task (Chief of Staff, owner: "Claude Code and Codex first, and anyother that can work properly"): find more engines, rank them against Security's bar (`docs/security/2026-11-18-cli-engines-requirements.md`, CE-1 to CE-9, with the S1/S2/S3 rulings), say which deserve a spike.

## The bar in one list (from Security's note and the Chief of Staff's message)

1. Headless run with structured output.
2. The owner's own models through an OpenAI- or Anthropic-compatible endpoint (Bunny's local endpoint, CE-4), no vendor account.
3. A host-approval channel that waits for Bunny before every command and write (CE-1.2: it can stay pending, a timeout means deny), or tools confined to a folder with commands off (CE-2.4).
4. Network off except the model; no forced telemetry; self-update off (CE-5.5, M5).
5. A free licence that allows bundling; Windows support.
Plus: the person's own config homes are never loaded (CE-3.3), prompt by stdin not the command line (CE-8.1), the engine's own web/MCP/subagent tools can be turned off (CE-8.3).

## Finding that changes the plan: Agent Client Protocol (ACP)

ACP is an open JSON-RPC-over-stdio protocol for exactly this host/agent split. Its `session/request_permission` has the agent ask the client before a tool call, with options `allow_once`, `allow_always`, `reject_once`, `reject_always`; the client answers with `selected` plus an option id, or `cancelled` if the turn is cancelled; "Clients MAY automatically allow or reject requests". [protocol: tool calls](https://agentclientprotocol.com/protocol/tool-calls). The official registry lists 51 agents, among them **Goose, OpenCode, Gemini CLI, Qwen Code, Cline, Codex CLI (through an adapter), Claude Agent (through an adapter), OpenHands, Mistral Vibe, Kimi CLI, Pi (through an adapter)**. [ACP agents](https://agentclientprotocol.com/overview/agents). The registry lists support; it does not say how well each agent honours the permission request.

Why it matters: one ACP client in Bunny (the official TypeScript SDK, `@agentclientprotocol/sdk`, is what Goose's own docs use) could drive several engines, and the answer to a request can wait as long as Bunny's Ask card does. That is CE-1.2's second option. **Caution for Security:** the spec says the agent "MAY" ask, so an agent in its own auto mode runs without asking. Each engine still needs CE-1.7/1.8-style second layers (deny rules in its own config, auto modes off) and the same fail-closed spike (S1(c) set) before it ships.

## Ranking against Security's bar, with the findings behind each

### 1. Goose (spike)

- **Fits:** Apache-2.0; a Windows CLI zip and a separate ACP binary zip in the release; documented path "launch `goose acp` as a subprocess ... receives streamed responses, tool activity, and permission requests"; telemetry off by default; `goose run` takes the instructions from `-i -` (stdin), so the prompt need not be on the command line (CE-8.1); `--output-format stream-json`.
- **Gaps for the spike:** the default mode is Autonomous ("applied by default"), so Bunny must set approve mode (`GOOSE_MODE=approve`) and prove that mode asks for every tool; how a headless `goose run` treats a tool that needs approval is not stated ("Uses configured defaults or fails safely" in a tutorial table; no detail). Its built-in extensions (`developer`, `computercontroller`) include shell and computer control, so CE-2.4 (commands off) needs a way to load none or only a file-edit extension: UNKNOWN. A home-override variable for CE-3.3: UNKNOWN. The secrets file lives under `%APPDATA%\Block\goose` when the keyring is off (CE-1.6 already denies `%APPDATA%` reads). Whether a custom OpenAI-compatible URL works without the "provider catalogue" is only partly shown (named providers use `*_HOST` variables).
- **R4 (free only):** nothing paid is needed with an own endpoint.

### 2. OpenCode (spike)

- **Fits:** MIT; Windows zip in the release; `run --format json`; a server API with list-pending and reply (`once`, `always`, `reject`) permission calls and an events stream; ACP with pending permission requests rejected on cancel; permission rules allow/deny/ask with "if no rule matches, OpenCode uses ask"; `external_directory` is its own rule; custom provider with `baseURL` and key from the environment, no account in the example; `OPENCODE_CONFIG_DIR`, `OPENCODE_CONFIG_CONTENT`, `OPENCODE_DISABLE_AUTOUPDATE`.
- **Gaps for the spike:**
  - The docs describe two versions. The current release is 1.19.6, and the pages under `v1/` use `permission`/`bash`/`task`; the newer pages use `permissions`/`shell`/`subagent` and say V2 features "aren't enforced in OpenCode 1". Pin one and read that version's page.
  - **Base policy is allow-all in the newer docs** ("all actions allow"; no default `external_directory` rule), so Bunny must write explicit deny/ask rules (CE-1.8 style).
  - Project config is loaded and merged from the working directory upward: a repo's own `opencode.jsonc` (plugins, MCP, commands) would load unless isolated (CE-3.3, R18).
  - Telemetry: no page found, UNKNOWN; a models.dev catalogue fetch and a local background service exist; probing local Ollama/LM Studio/vLLM ports is documented.
  - Docs recommend WSL on Windows; native Windows is "can run". The ACP `session/load` needs the session's own cwd.
  - A `share` feature exists (not read in detail): must be off.

### 3. Qwen Code (spike, second)

- **Fits:** Apache-2.0; `--output-format stream-json`; **SDK `canUseTool` callback, auto-denied after 60 s** (so a timeout is a deny, CE-1.2); `permissionMode`, `coreTools`, `excludeTools` and `allowedTools` options; `modelProviders` with `baseUrl` and `envKey` for `openai` and `anthropic` protocols (credentials read from the environment, never saved); Plan mode is read-only.
- **Gaps:**
  - **Default mode is Auto**, where an LLM classifier approves "safe" actions: this would use the model to approve its own commands. Bunny must force `default` (Ask Permissions) and test it.
  - Usage statistics default **on**; update checks default **on**; both have off switches.
  - Stream-json input "is currently under construction"; the SDK is the supported route. Its sandbox is Linux only ("`tools.executionSandbox` ... Linux policy").
  - No Windows binary asset in the release read: install by PowerShell script or npm. Qwen's own sign-in (Qwen OAuth) is a separate path, not needed with an own endpoint.

### Not now or no

- **Gemini CLI:** best structured output and a policy engine with `ask_user`, plus ACP. But the model side is Gemini only: auth is Google sign-in, a Gemini API key or Vertex; the only URL override is `GOOGLE_GEMINI_BASE_URL` (HTTPS or loopback) for the Gemini API shape. Bunny's local endpoint speaks OpenAI and Anthropic shapes, so a Gemini-shaped translation would be needed. Fails "owner's own models" as the endpoint stands. Revisit only if a Gemini-shape adapter is wanted.
- **Kilo CLI:** MIT, Windows zip, `kilo run --auto` (all prompts auto-approved unless a rule denies, so it needs rules), telemetry on by default (`KILO_TELEMETRY_LEVEL=off`), pushes its own account and hosted models. Its release assets and `run` command mirror OpenCode's naming, but I did not find a source stating the relationship. Hold until OpenCode's spike shows what carries over.
- **Crush:** the licence is FSL-1.1-MIT. Its "Permitted Purpose" is "any purpose other than a Competing Use", and a Competing Use is "making the Software available to others in a commercial product or service that ... offers the same or substantially similar functionality". Bunny shipping an AI coding agent inside its installer can be read as that. It converts to MIT only later (FSL's usual two years, not read in this file's excerpt). So **bundling fails the free-licence line**; downloading it for the owner's use on their own PC is "internal use" but still a licence call for the owner/legal. Non-interactive mode was not documented on the pages read.
- **Roo Code:** archived 2026-05-15, shut down. Reject. (**Kimi CLI** is archived on GitHub too.)
- **Pi:** MIT, JSON/RPC/SDK, but its README says it "does not include a built-in permission system"; it runs with the process's rights. Fails CE-1 as an engine unless Bunny wraps it in a container, which is a different project.
- **Mistral Vibe:** Apache-2.0, a programmatic mode and a telemetry off key, ACP listed; custom endpoint, permissions and Windows run details not read (Windows needs `uv`). Not enough to rank; add to a later round.
- **Not read at all:** OpenHands (MIT, ACP listed), Continue CLI (Apache-2.0), Plandex, Amp, Droid, Copilot CLI (the last three are vendor-account products and fail "no account" by their nature, not checked).

## Recommendation

1. **Spike Goose and OpenCode first**, with one shared ACP client written once, because both document ACP permission requests and both take an OpenAI-compatible endpoint. Qwen Code third, through its SDK `canUseTool`.
2. For each, the spike repeats Security's set: (a) a prompt that asks for a command, a write and a read outside the folder: each must reach Bunny's card (or be denied) and nothing runs on a missed card; (b) the S1(c) failure set (client killed, garbage reply, timeout, closed pipe) must all end in deny; (c) the fake-home test (CE-3.3) with a hostile `.opencode`/`.goose`/`.qwen` in the project and in `USERPROFILE`; (d) a network capture at the fake upstream: only the model call in local mode, with telemetry, update and catalogue fetches off; (e) the engine's own web/MCP/subagent tools off (CE-8.3); (f) commands off for restricted mode (CE-2.4).
3. **Do not pick on the agent's word that it asks.** ACP says "MAY"; prove each mode on the real binary.
4. Licence and R4: all three are free and need no account with an own endpoint. Re-check each licence at the pinned version (CE-5.4).
