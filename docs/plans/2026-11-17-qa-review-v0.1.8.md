## 4. Every gap QA knows of, in one list

**A. Shipped open (known before release)**
1. **RO-1** (read-only labels): a connector tool counts as "read-only" because the connector says so (`src/server/mcp.js:108`, `src/server/mcpLocal.js:187`). A careless or hostile connector can label a write tool read-only: it then skips the Ask question and is offered in Plan mode. The fix (a "Trust read-only labels" button) is in W4-11, which was left out.
2. **P-6** (plugins in Auto): `install_plugin`, `add_skill` and `add_connector` are risk `edit` (`src/server/appTools.js:11`), so in Auto they run unasked: a stranger's skill text becomes system text in every later reply and its connectors are switched on. Only a local connector asks in Auto (W3-3).
3. **L-4** (secrets): a local connector's `env` values (often API keys) are kept in plain text in `mcp.json` (`src/server/mcpStore.js`, `cleanLocal`), unlike provider keys.
4. **OAuth sign-in address check**: private and loopback addresses are refused by their NAME (`src/server/mcpOAuth.js`, host rules); a public-looking name that resolves to a private address is not caught (code reading; I did not test with DNS).
5. **W4-11 audit items not shipped**: a provider or model that refuses tools fails the whole reply (PV-1); more than about 100 connector tools breaks the request (PV-2); no initialize handshake or session id for remote connectors (R-2); long skills are cut in the middle (S-1); connector results reach the model as raw JSON and an error shows as done (D-1); only the first page of a tool list is read (R-5); Stop does not end a connector call (R-7); the model is not told which connectors exist or what they say about themselves (L-1, L-2); plugin layouts and `.mcp.json` entries are mostly missed (P-1, P-3). All were fixed on the W4-11 branch and passed my walks there.
6. **W4-11 branch findings** (if it ships later): P-1 also imports skills inside `node_modules`, test fixtures and examples, with no cap; PV-1 is not remembered per model (a failed request and a notice on every message) and also reads a 400 about "tool-capable" as a tools refusal; R-5 stops after 20 pages without saying so; editing a connector's address can create a duplicate; uninstalling one plugin removes a connector another plugin reuses.

**B. Found by QA walks, shipped, not blocking**
7. Model picker group labels (Provider, Can do, Sort): 3.1 to 1 in light and 3.7 to 1 in dark.
8. The amber model-switch line is 3.3 to 1 in the light theme.
9. The "no provider has it left" line shows the raw model id and names only the first failing provider, in nested brackets.
10. The question guard (`asksToRunCommands`): a choice such as "I will run the commands myself" is no longer caught; it also misses "I need you to run…", "Open a terminal and run…", "You'll need to run it yourself", "Kindly run…", "Let me know when you have run…", "Run … on your machine", "Would you mind running…"; and "Would you like me to type the command into the terminal?" is caught wrongly.
11. A typed stop that begins with a go-ahead word and "no", "not" or "don't" ("yes, no problem", "continue, don't stop") stops the work (safe direction); "continue? no, stop" still carries on.
12. A scheduled prompt of about 1,941 to 2,000 characters is refused although the message says "over 2,000": the card heading is counted.
13. LA-4b: a stopped search says "after 5 s" but one file stops after about 1 s.
14. Never run: the 30 minute question wait itself, the 120 s command default, a 10 minute `run_command`, the full 5 minute connector first start, a real successful `download_file`, a real provider, a real OAuth sign-in.
15. **Updater**: a release that has no `latest.yml` is downloaded and accepted with **no checksum check** (`electron/updater.js`, `readRelease` leaves `sha512` empty and `download` skips the check). The published v0.1.8 has `latest.yml`, so it is not affecting it; a mistaken or hostile release without one would skip verification. Also the version comparison ignores a pre-release suffix (0.1.8-rc1 equals 0.1.8).
16. The release notes say "Pictures" and "Images" where the filter chip is "See" and "Image".

## 5. The real Electron window (added after the project's Electron was installed in the QA worktree)

Run on the published v0.1.8 source (`af77b62`) with the project's own Electron 45.3.2 (from `npm ci` and the package's install script), on an invented profile: `BUNNY_DATA_DIR` and `--user-data-dir` were temp folders, `%LOCALAPPDATA%\BunnyAI` was not read or written (its last-modified time was unchanged), the updater was off, and `launchAtLogin` was never touched. Walk: `e2e/w018-electron.mjs` (20 of 20 rows run), probes `e2e/w018-electron-probe.mjs` and `e2e/w018-electron-spell.mjs`.

- The window opens, is visible at 1320 x 860 and titled "Bunny AI"; the page sees only `window.bunnyDesktop` (no Node, `require` or `process`).
- A write of a window-only setting from the page without the bridge is refused (403); the same write through the bridge (the real main process) works; a chat that sets the permission mode directly is refused (403).
- Quick ask: off by default; with the tray on, switching it on with Ctrl+Alt+Space answers "That shortcut is already used by another app" (the owner's installed copy holds it on this PC); changing the shortcut to Ctrl+Alt+Shift+Q registers it for real; turning the tray off turns quick ask off and unregisters it.
- Spell check: en-US is loaded; a word typed in the message box ("teh") is flagged and the real right-click menu shows suggestions (the, ten, tea, tee), "Add to dictionary", then Undo, Redo, Cut, Copy, Paste, Select All. (A value set from a script is not spell-checked, only typed text.)
- A second launch on the same profile does not open a second window (single instance).
- **Not run (EL12 to EL16)**: the real Ctrl+Alt+Space delivered by the operating system, the bar opening, its + menu in the real window, Enter opening a new chat, Esc closing. They need keys sent through the OS; the auto-mode classifier refused that, so it was not done. The bar page itself passed 89 of 89 in Chromium and the controller 22 of 22 with fake Electron objects.
- New finding: the shortcut rule accepts any Ctrl, Alt or Win plus one key (Ctrl+C, Ctrl+V, Ctrl+A, Alt+F4 are allowed), so a person (or a script through the bridge) can make Bunny take those keys system-wide while quick ask is on; a first run registered Ctrl+A as a real global shortcut for about a second.
- Observation: when the chosen shortcut is already taken, the saved preference says quick ask is ON (with the error message), and changing only the shortcut afterwards turns it OFF; the Settings page sends both together, so the person sees the message and can pick another.
