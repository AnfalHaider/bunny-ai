## SEARCH-PC: search this computer from the Quick ask bar

The owner's words (typed in the Chief of Staff's chat, 2026-11-18):

1. "i have a question, can we some how link windows search behind it also? lets say i want it the quick bar to search for something on my computer and tellme about it, is that possible?"
2. After I explained it was possible and asked whether to plan it for v0.1.14 or v0.1.13: "since its on my system i am not concerned about the privacy. so there should be an option to enable read file then talk or or not. add it to the wish list for 0.1.14."

What it means:
- A read-only "Search this PC" tool for the Quick ask bar (and the chat), using the Windows Search index: names, folders, dates, snippets. It covers what Windows indexes, with no indexing of Bunny's own.
- A setting chooses what happens after a search: **read the file, then answer** (Bunny opens the best matches and answers from them, with links to the files), or **show what was found** (Bunny lists matches and reads a file only when asked). The owner wants this choice to exist.
- Folders excluded in Bunny's settings stay excluded.

Risk: HIGH (a new capability reading files outside the project folders, and sending their contents to the model). This entry records the owner's wish, not the go to build: the owner's go is asked with the drawing. Design draws first, then Security sets requirements, then it is built.

## PHONE-LAYOUT, WEBAPP-SIGNIN and OPEN-SIGNIN

The owner's words (typed in the Chief of Staff's chat, 2026-11-18): "i noticed another thing, that i want fixed in 0.1.14, when i open the applicaion on mobile the layout is broken and not dynamic, also if i install the applicaiton through browser it does not allow me to sign in even with the correct code, lets make the privacy policy a bit loose, meaning anyone with access to the URL and passcode defined in the settings, should be able to sign in."

- PHONE-LAYOUT (MEDIUM): on a phone, Bunny's layout is broken and doesn't adapt. QA walks every page at phone widths, in both themes, in the browser and as an installed web app, and lists each break. Design draws the fixes (today beside proposed), then they are built.
  - The owner's example (a phone screenshot of a new chat in Chrome over the home network, 720 px wide; the picture stays off the repo because it shows the real profile): the composer runs off the bottom of the screen (the row under the box is cut, and Send is cut at the right edge and the bottom, likely 100vh against the phone's moving address bar instead of dynamic viewport units); the model chip "Auto · nvidia/nemotron…" runs under Send; the top bar spreads seven controls across the width with "Export" as a word among icons; the empty-chat hint still says "Pick a model, then type below." while Auto is chosen.
- WEBAPP-SIGNIN (bug, MEDIUM to HIGH): Bunny installed from the browser (the home-screen web app) refuses sign-in even with the correct passcode. Find the cause first: a standalone app's separate cookie store, the cookie's SameSite or Secure flags over plain HTTP, the sign-in redirect leaving the app's scope, or the service worker. Security reviews the fix.
- OPEN-SIGNIN (HIGH, a security control): the owner wants a looser rule: "anyone with access to the URL and passcode defined in the settings, should be able to sign in." The owner's go on this is given here. What it removes must be confirmed with the owner before building: which of today's limits block a person who has the URL and the passcode (for example a local-network-only rule, or the device level), and whether "anyone with the URL" includes reaching Bunny from outside the home network. Security sets the requirements.
  - I asked: "When v0.1.14 starts, should "anyone with the address and passcode" include reaching Bunny from outside your home network, over the internet, or stay on your home network only?" Owner: "include outside the home network too" (typed in the Chief of Staff's chat, 2026-11-18). So OPEN-SIGNIN includes reaching Bunny over the internet. Researcher and Security pick the safe way first: HTTPS is required over the internet (the passcode and chats must not cross the internet in plain HTTP), through a free option (for example a tunnel or a mesh VPN the owner turns on in Settings) rather than forwarding a router port. Sign-in limits and the action log stay. Free only (R4).

## CLI-ENGINES: Claude Code and Codex CLI as engines behind Bunny's interface (v0.1.14: the owner, typed in the Chief of Staff's chat, 2026-11-18: "And i want it built in the next build")

The owner's words (typed in the Chief of Staff's chat, 2026-11-18):
1. "can we integrate claude CLI, Codex CLI, Cursor CLI, Cline CLI, Aider CLI, in the application back end use it also, with the option to pick one from settings, we use the CLI's and it operates on the models we provide ... my theory is that we keep the defualt as it is, but with option to choose one form the setting also, if we choose one, they run in the backend with our UI/UX in the front. discuss."
2. After I recommended Claude Code and Codex first, as the v0.1.15 headline, with a Researcher feasibility report now: "Yes, lets go with claude and codex , also the cli's should be bundled in the application, with the option to update them from within the application also."

What it means:
- Bunny's own engine stays the default. Settings offers Claude Code or Codex CLI as the engine; the chosen CLI runs hidden and Bunny draws its steps, tools and edits in its own chat.
- The CLIs use the models Bunny provides: Bunny serves a local OpenAI- and Anthropic-compatible endpoint and routes requests to the owner's providers and keys.
- The CLIs are bundled with Bunny, and can be updated from inside Bunny (Settings), pinned to tested versions.
- Bunny's permission rules, protected folders, device levels and action log must hold for the CLI engines (mapped onto each CLI's own permission settings).

To find out first (Researcher, then Security):
- Each CLI's current headless mode and structured output, custom-model support, and licence. Bundling: Codex CLI is open source; whether Claude Code may be redistributed inside another app must be confirmed from its licence and terms. If it may not, the fallback is that Bunny installs the official package on the owner's click and updates it from there.
- Free only (R4): no paid account required for either path.

Researcher's report (e462903 on claude/researcher-cli-engines): Codex is Apache-2.0 and may be bundled, but speaks only the Responses API, so Bunny's endpoint translates; Claude Code is all rights reserved, needs Anthropic's Messages format and a paid Anthropic account, is not supported with non-Claude models, and may be preinstalled only unmodified with each user's own Anthropic credentials; both are about 380-390 MB, so download on click is better than the installer. I asked: "How should v0.1.14 handle the engines? 1. Codex only (recommended) 2. Codex, plus Claude Code with your own Anthropic account 3. Something else". Owner: "Claude Code, Codex CLI, Aider, Cline , add all these." (typed in the Chief of Staff's chat, 2026-11-18).

So v0.1.14 carries four engines: Claude Code, Codex CLI, Aider and Cline. Claude Code runs with the owner's own Anthropic account and Claude models (the owner's choice after being told it needs a paid account: the owner's exception to the free-only rule R4, for this engine only); it is installed on the owner's click, unmodified, and the owner signs in to Anthropic personally. The others use the models Bunny provides. Each is downloaded on click and updated from Settings, pinned to a tested version. Researcher adds Aider and Cline to the report (headless mode, structured output, custom models, licence, Windows packaging, free).

Risk: HIGH (a new execution engine, permissions, bundled third-party code, a local model endpoint). Design draws the Settings and update screens; Security sets requirements; the owner's go is asked with the drawing.
