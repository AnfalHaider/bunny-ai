# v0.1.16 direction: Bunny works like Claude Code and Codex

## The owner's words (typed in the Chief of Staff's chat, 2026-11-20)

On engines and instructions: "What's confusing me is technically now we would have three engines: the Bunny engine, Codex engine, and Claude engine. What if the instructions for all three are divergent for the same project? That would probably make issues."

On Bunny's own engine: "Claude Code or even Codex, they're pretty refined... when I ask them to do something, they do it properly without getting stuck in a lot of other or different permissions... They can identify the browser tools that are required or computer use tools that are required, and Bunny simply does not do that... Bunny should be operating more like Claude app does or Codex app does, probably following the permissions and rules and accesses it has. It should be self-aware to a level. When I ask it to do something, it should know whether it has those tools or not. If not, it should be looking for those tools, downloading it. It just shouldn't give me an error. It should start working on the task and have the required tools like Claude or Codex does."

On Quick ask: "when I invoke it and I ask it... I find a file that says tax returns, it should just simply do that, rather than getting stuck and telling me to open the app. And when I ask it to tell me, let's say, what's the weather like in Islamabad, it should know that that information requires internet access, and then it should search the internet... As of right now, I feel Bunny is very flaky about it."

Bringing it together: "I want a fluid, functional, refined user experience and the app with the probably the same permissions or access levels that ditto Claude app or let's say Codex or even Open Code for that matter. And I want it to be functional like that. Also, there's a lot of things in the settings that I don't think they work, or whether if they work, they're not properly, like they're not probably very clear. So the overall app experience needs to be improved. As far as the question about three engines working... Let's say the user is running one engine for a project and they want to switch engines midway for whatever reason. If they switch the engine should read the same files the Bunny engine or Claude engine was already working on... So Codex should read those files also. It should know what we're talking about."

## Workstreams

1. **AGENT-FLOW:** Bunny knows its tools, switches on or finds what a task needs (asking once where it must), and starts working instead of erroring. Tech Lead's diagnosis comes first (claude/tech-lead-agent-flow).
2. **PERMISSIONS-LIKE-CLAUDE:** permission modes and access levels that match Claude Code, Codex and OpenCode (absorbs PERM-REFINE). It changes permissions, so it's HIGH: Researcher compares, Design draws, Security reviews, and the owner gives the go before it's built.
3. **SETTINGS-OVERHAUL:** QA checks every setting (does it work, does it stick, is it clear); then Design proposes a clearer Settings, today beside proposed.
4. **ENGINE-SWITCH:** change a chat's engine midway. The new engine gets the same folder (or worktree), the same project instructions, and a handover of the conversation and the files touched, so "it knows what we're talking about".
5. **ONE-INSTRUCTIONS:** one shared instruction set (AGENTS.md, falling back to CLAUDE.md) for all three engines, so they never diverge. This replaces the per-engine reading in the FOLDER-RULES drawing; the trust card and limits stay.
6. **REWIND:** as drawn (pending the owner's OK), aware of engine switches.
7. **QUICK-ASK-JUST-WORKS:** the bar answers web questions and finds files without sending the person to the app. Search this PC on by default for finding only needs the owner's explicit words; Security has given the conditions.
