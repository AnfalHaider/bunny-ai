### 4c. What QA found (all non-blocking)

1. **Real hotkey and bar window not run.** The real Ctrl+Alt+Space, the real quick-ask bar window and the real file dialog need OS-level keys, which QA may not send. They were checked with a stand-in Electron, the real logic, the real bar page and the real chat page (`w019-w48b-file`, `w019-qabatch`).
2. **Real 0.1.8 to 0.1.9 update on an installed copy** is not run (never installing over the owner's copy). Metadata, checksum refusal and version order are proven; the real 122 MB download and install are not.
3. **Thinking choice is stored per model id**, so the same model name on two providers (for example the same open model on Groq and Cerebras) shares one choice. Levels are checked per provider, so a level the other provider lacks is ignored, but the choice itself is shared.
4. **W6-19 job words are broad.** "match the regex on the page", "copy the page title into the readme" and "clone the website repository" count as picture jobs. In Auto that is harmless. For a model picked by hand that cannot see, it gives a false "cannot look at pictures" line.
5. **W6-25 nudge fires once** per wait and never repeats. A card left for an hour gets one nudge.
6. **A failure note from an earlier, separate message is kept** when a new non-retry message is sent (the red note stays above the new reply).
7. **Updater is strict about the sha512 text.** A double-quoted YAML value is refused, as are hex and next-line values. electron-builder writes it plain, so it is fine today.
8. **The memory slot is app-wide.** Only one request body over 1 MB is read at a time across the whole app, so one slow large upload delays every other large upload (photo, import) until it ends or disconnects.
9. **Stale comment:** `src/server/mcp.js` says a tool list is followed for at most 20 pages; the limit is 100. The behaviour is right and bounded (100 requests, 51 ms in my walk).
10. **Search-stop wording:** the "Search stopped after 5 s in all" message could not be reproduced with a 12-file fixture, which stopped on the first file under the one-second message. The one-file message is proven. Please confirm the "in all" message with a test that has many files, each just under a second.
11. **Plan mode and untrusted connectors:** Plan mode now offers no tool from a connector whose labels were not trusted, even ones labelled read-only. This is deliberate. The release notes say read-only tools run without asking only while the labels are trusted, but do not say Plan mode also offers nothing before trust. Worth a line in the help text.
12. **Walk scripts for W4-11 (v0.1.8 era)** `e2e/w411a-*.mjs` and `e2e/w411b-*.mjs` still carry four stale expectations (Plan-mode offering of connector tools, the picture note, the page bound of 20; the Plan-mode one appears in two walks) that no longer match the deliberate behaviour. They are kept as they are; the current expectations are in `e2e/w019-w411.mjs`.
13. **Shipped probe:** `test/probes/views-smoke.cjs` at 9ae0df9 passes 10 of 10 on a real display. Its window sits off screen, so on a display where an off-screen window does not paint, the screenshot step can still fail (LOW, Builder B). My extended copy (`test/probes/qa-w624-smoke.mjs` with `qa-run.cjs`, visible window) passes 21 of 21, including the isolated world and the download cancel.
14. **Notes cut:** see section 3 (in-app notes show 4,000 of 4,107 characters).
