# W6-0 rehearsal: the owner's acceptance task, run with a scripted model

QA, 2026-11-16, on `main` at dfac0db (v0.1.6). Plan row: W6-0 in `docs/plans/2026-11-16-0.1.6-plan.md` (Wave 6).
Walk script: `e2e/w6-rehearsal.mjs` (committed with this report). It tests the plumbing, not model quality.

## How it was run

- Invented profile: `BUNNY_DATA_DIR` in a temp folder, `BUNNY_FAKE_UPSTREAM=1`, a fixed test token. Never the owner's profile.
- Local fixture repo: a small git repo whose README says "npm install, then node index.js", with one `file:` dependency so `npm install` needs no network.
- Local fixture site: a static page served on a free localhost port, with a header, nav, a hero background image, an `<img>`, a web font, a stylesheet and a script that adds a paragraph after 300 ms.
- A scripted OpenAI-compatible "model" asks for the steps a real model would, in this order: update_tasks, search_plugins, read_url, install_plugin, `git clone`, read_file README, `npm install`, `node index.js`, ask_user (the use case), browser_open, browser_read, download the assets with `Invoke-WebRequest`, write_file (page), write_file (a 150 KB page), write_file (a small server), start_process (the copy), browser_open (copy), screenshot, browser_open (original), screenshot, ask_user ("does it look right", answered after a 20 s wait).
- The browser panel is played by a real Chromium page that answers the server's `browser` events the way the desktop panel does (open, read, screenshot).
- Model failure: three scripted providers (A, B, C) behind the same fake; A fails after step 11 with HTTP 500, HTTP 429, a stream cut mid-sentence, or a stall (never a byte). Auto mode, driven by the real client in `src/ui/chat.js`.
- Everything it starts (app server, fixture site, copy server, browsers) is stopped when it ends. Checked afterwards: no listener on any port it used, no process left, no chrome it started.

```
SRC=<worktree at dfac0db> OUT=<folder> node e2e/w6-rehearsal.mjs            # S1..S9, the API walk
MODE=ui SRC=<worktree> OUT=<folder> node e2e/w6-rehearsal.mjs               # F0..F4, the real client's fallback
```

Scenarios: S1 whole job, no failure. S2, S3, S4, S5: failure after step 11 (Auto, API only: no client, so no fallback is expected there; they show what the person sees when the client does not retry). S6 35 small tool calls in one reply. S7 a 156 KB file read three ways. S8 a command that runs 125 s. S9 the whole job in Manual. F0 to F4: the same job through the real client in Auto, with and without a failing model.

## What this rehearsal could not reach (UNKNOWN)

- The real repository `github.com/morluto/rea` (network, and the layout decides how it is installed and used).
- The real site and its asset set (framing, fonts, animation, lazy images), the Electron panel itself, and vision from a real model.
- Real providers: how the owner's keys rank, and how long a real model takes to fail or stall.
- `request_capability` flows and the other computer-use route (`computer_*` tools) were not tried: they need the desktop shell.
