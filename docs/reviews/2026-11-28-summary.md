## 3. "Works on its own and smart": what is missing

Bunny already has the building blocks: a task checklist, helpers, rewind, model hand-over, the Auto check and tool discovery. What stops it finishing long jobs on its own is **follow-through and resilience**, not missing features:

1. **One provider hiccup ends the job.** A busy (429), server (5xx) or stalled reply after the first step stops the whole run, with no retry. *Checked by me:* there is no 429 or 5xx retry in `src/server/chat.js`. Fix: retry with a short wait. **Size S. The single biggest win.**
2. **Long jobs overflow the model's memory.** The context limit is a fixed 240,000 characters, and only in Code chats (`app.js:4651`, checked). Ordinary chats have none, and small-window models overflow. Fix: size it from each model's real window, in every chat. **S–M.**
3. **Nothing makes it check its work.** A reply can edit files, run nothing, and say "done". Fix: a "check your work" step when files changed and nothing was run, or a verify-before-done rule. **M.**
4. **The "you still have open steps, carry on" nudge only works in Code chats** (`app.js:4685`, checked). Fix: use it in every chat. **S.**
5. **Schedules and helpers have no fallback model**, because the Auto ranking lives only in the chat route. Fix: one shared module. **M.**

## 4. Safety before Bunny works longer on its own

These are Security's five "fix before more autonomy" items. All are HIGH, so each needs your go. Anything that adds a card goes to Design first.

| | Today | Fix |
|---|---|---|
| **N1** | In a full chat, Bunny can open any public web address without asking. An injected page could send your data out inside an address. | Open addresses you typed, ones a search listed, or links on pages already opened. Ask for anything else. |
| **P2** | `remember` saves a memory that goes into every future chat, without asking. | Ask, unless you asked it to remember. |
| **P3** | Creating a schedule doesn't always ask. A schedule is code that runs with nobody there. | Always ask. |
| **S1** | Background helpers can't be stopped. *Checked by me:* no abort signal at `app.js:3537`. | One Stop ends everything a chat started. |
| **S-H1** | A scheduled run that hits a card waits forever, with nobody to answer. | The run ends with a note and a notification. |

Also: in Auto, edits inside the project folder skip the check (`app.js:4327`, checked; G2-1). So a chat can edit a script and then run it. Fix (J1): send edits to run-later files (scripts, package files) to the check.

## 5. Simplify: where Bunny is busier than Claude

Bunny has nearly every screen Claude has. The gap is **how much you must decide and read**. Design's top picks:
1. **One chip in the message box.** Today there are four separate controls (model, permission, effort, route) and a fifth in Code. Make it a model chip with effort inside, and one clear permission control.
2. **First run.** Today you hit "Add a provider" and a 25-entry list. Offer two buttons instead: **Use a model on this PC** (Bunny local) and **Connect a provider**.
3. **Settings.**
   - One sentence per row, where rows carry 300–900 characters today.
   - Retire the 10,753-pixel standalone Settings page.
   - Memory in one place, not three; Skills and Connectors in one place, not three.
   - Search that finds rows, not just sections.
4. **Side panels.** Dock them beside the chat instead of floating them over it. Use the same name on each button and its pane.
5. **Mode names.** Name them by what happens: **Ask first**, **Smart**, **Do it all**. "Smart" alone says nothing.
6. **Long jobs.** A plan-and-progress card at the top. A one-line activity trail under each reply ("read 4 files, edited 2, ran 3 commands · 41 s").
7. **Projects.** A real project page: instructions, files, default model and mode, and its chats.

QA's extra finding: the same setting is called "Ask each time" in one place and "Manual" in another. Right after you connect a provider, the first chat can be blocked until you press **Show all models**.

## 6. Why the same kinds of bug keep coming back

Tech Lead found four repeating causes. Each fix stops the whole class of bug:
- **Stale values.** The cold-start bug is an example. Read the address and key fresh on every round.
- **Test mode hiding real behaviour.** There are 21 places where test mode takes a different path. Keep the stand-ins at the outer edge only, and keep a real-runner test in the gate for every runtime.
- **Window-only pages.** The Activity-list bug is an example. One shared list, plus a gate check that walks the pages in the real window.
- **Errors recognised by their wording.** Give errors typed codes.

Plus the two biggest code files, which are huge: one function holds 148 routes, and its chat part is about 2,250 lines. Split them in move-only steps.

Full review: [2026-11-28-tech-lead-architecture.md](2026-11-28-tech-lead-architecture.md)

## 7. Recommended order

| Phase | What | Why first |
|---|---|---|
| **A: resilience** (v0.1.17) | Retry with backoff; context sized per model; the open-steps nudge in all chats; the v0.1.17 carry-overs | Small, low-risk, and the biggest effect on "finishes on its own" |
| **B: safety for autonomy** (v0.1.17–18, needs your go) | N1, P2, P3, S1, S-H1, J1 | These have to hold before Bunny is trusted to run longer |
| **C: follow-through** | Check-before-done step; plan-and-progress card; activity trail; schedules at a set time | Makes long jobs visible and reliable |
| **D: simpler UI** (drawn first) | One chip; first-run two buttons; Settings trimmed and merged; docked panels; clearer mode names | The biggest "feels like Claude" gains |
| **E: parity features** | Project files with search; editable memory; Research mode | The largest Claude gaps you'd notice daily |
| **Ongoing** | Split app.js and chat.js; one window-only list; typed errors | Ends the bug classes that keep coming back |
