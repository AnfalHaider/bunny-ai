# UX review: Bunny AI against the Claude app

Design role · 2026-11-28 · main @ bb229a0f (v0.1.16) · read-only review, no drawings yet.
Asked for by the owner (relayed by the Chief of Staff): "parity with Claude app … powerful enough to work on its own and smart."

## How this was done, and what it does not cover

- **Build:** `git archive bb229a0f`, run on an invented profile (`BUNNY_DATA_DIR` in a temp folder, `BUNNY_FAKE_UPSTREAM=1`, `BUNNY_FAKE_LOCAL=1`; the person is "Sam"). A test Anthropic key was typed into the Providers screen, so replies are canned test replies. Nothing touched `%LOCALAPPDATA%\BunnyAI`.
- **Browser walk:** Chat, composer menus, picker, slash menu, message actions, sidebar and phone drawer, header panes, Code tab, new project, Providers, Customize, Automation, the in-app Settings window (list, Appearance, Models, Permissions, Quick ask, Capabilities, search) and the long standalone Settings page. At 1100 px and 390 px, light and dark. No sideways overflow on any screen. One console error everywhere: a 404 for a favicon.
- **Real Electron window:** chat at 1100 and 704 px (the window's minimum), the Settings "Desktop app" and "Quick ask" sections.
- **Not covered, so do not read silence as a pass:** the Quick ask bar itself (global shortcut; no window to drive), real model replies and long chats, a Code chat in a real git folder (Changes, Terminal and Files panes were empty), projects holding files, the artifacts panel, voice, sign-in screens, the phone as an installed app over the network, dark theme inside the real window (the window ignored the OS dark setting, so dark comes from the browser). The 704 px window and the browser were each checked once, not across every screen.
- **Pictures** are in `docs/reviews/2026-11-28-design-ux/`, all from the invented profile.

## The short version

Bunny already has most of what the Claude app has: chats, recents, projects, artifacts, incognito, search, a model picker, message actions, slash commands, a Settings window with a left menu and search, a phone drawer. The gap is not missing screens. It is **how many things Bunny asks the person to decide and read**.

1. **A person must make four choices before the first message** (model, permission mode, effort, and in Code an engine), where Claude shows one chip. Most of Bunny's selling point ("smart", "works on its own") is hidden behind the words "Smart" and "Auto" that mean different things in neighbouring controls.
2. **Settings is a wall of paragraphs.** Descriptions of 300 to 900 characters sit on single rows (Brave key, Permissions, Search this PC). The same subject (memory, skills, connectors) lives in two or three places.
3. **The first run dead-ends in a provider list.** With no model, the page says "Add a provider" and opens a 25-entry list under a custom-provider form. Bunny local (no key, no account) is the best first answer for "work on its own", and it is listed under "Available: on this PC", below the form.
4. **Side panels sit on top of the chat** instead of beside it, covering the model chip and the header buttons that switch panels.

## Where Bunny should look and feel like Claude, and where not

**Look like Claude (the owner's parity goal):**

- A calm reading column: one message list, plain user bubble, no chrome around the assistant's text. Bunny already does this.
- One model chip in the composer, with effort folded into it; a "+" menu for everything that adds to a message (files, photos, connectors, search this PC, projects).
- Left sidebar order: New chat, Chats/Search, Projects, Artifacts, Recents, with the profile row at the bottom. Bunny is close; extra rows (Incognito, Import chat, Archived) should live in menus.
- Settings as a window: left menu, search, one section at a time on a wide screen; list then page on a phone. Bunny's window already does exactly this; make the standalone long page go away.
- Plain, short labels and one sentence of help per row. Bunny's help text is where it is furthest from Claude.
- Empty states say what to do in one line with one button.

**Do not copy Claude (Bunny's reasons to exist):**

- **It runs on this PC and shows it:** the "Local" chip, Bunny local with fit badges, "your files stay here". Keep, and make them more visible, not less.
- **Permission control is the product.** Claude hides it; Bunny's customers choose how far the AI may go. Keep the modes, but explain them once, in plain words, and show what the AI did (a short activity trail).
- **Code and tools live in the same app.** Keep the Code tab and its panes, but make them follow Claude's side-by-side pattern.
- **The bunny voice** ("I'll do the hopping") is the brand. Keep one greeting line; drop the second line and the third.
- **Honest limits** ("can't check where it came from", "Only this window can…") stay; they just need to be short and sit behind a "Learn more".

## Screen by screen

### Chat and composer (`src/ui/index.html`, `src/ui/chat.js`)
Pictures 01, 02, 03, 05.

- **Today:** under the message box there are four separate controls: model chip (inside the box), "Smart ▾" (permission mode), "Medium ▾" (effort), "Auto · Chat ▾" (what routes the reply). A fifth, the engine chip, appears in Code. Each is a different shape and style. Claude: one chip, and the "+" menu.
- The routing line above a reply reads "Auto · Code → offline/bunny-code". Useful for a power user, noise for everyone else.
- The "+" button opens a file dialog directly; it is not a menu. Claude's "+" is where connectors, search and projects live, so every capability has one obvious door. Bunny's equivalents are scattered (Settings, Customize, the Permissions menu).
- Slash menu has six commands and is good. The hint line "Enter sends · Shift+Enter new line · /compact frees context" is fine on a desktop and is hidden on a phone.
- The header carries Export, a context meter, and six icon buttons (Session overview, Terminal, Changes, Browser, Files, Tasks and plan) plus "open in own window". In a Chat (no folder) most of them are empty or irrelevant. Claude's header has the title and a share/menu.
- Message actions: Copy, Retry, Save as artifact, Read aloud, Branch (assistant), Copy, Edit, Branch (person). Complete, but "Save as artifact" and "Branch" are rarely wanted and take the same weight as Copy and Retry.

### Sidebar and navigation
Pictures 06 and 01.

- **Today:** brand and a Chat/Code switch; New chat; Incognito; Artifacts (count); Search chats; "Projects: All chats ▾ ＋" (a selector that doubles as the project list, with a tiny plus); Recents grouped by day; Import chat; Archived; profile row with a "Local" chip and a theme icon. Each recent chat repeats the full first message, with a green "Ready" badge on every finished chat.
- **Harder than Claude:** the Projects block is a dropdown, so a person cannot see their projects; creating one opens a form in the sidebar (name and "standing instructions"). "Ready" on every chat is a signal that always says the same thing. Import and Archived take prime space for rare jobs. The gear/theme icon at the bottom opens Settings; there is no label.
- **Phone:** the same sidebar slides over the chat as a drawer. It works.

### Projects
Picture 02 (sidebar), and the project form.

- A project is a name and "standing instructions". No files, no knowledge, no per-project model. In the browser, nothing explains what a project does for a chat. Claude's projects show their files and instructions as a page. Today's Bunny project is a filter, not a place.

### Code chats
Pictures 04 and the Code-tab screen.

- Chat/Code switch at the top of the sidebar is a good split. The Code composer adds "No folder" and "No branch" chips and says "Choose a folder below, then ask Bunny…". Good. But with no folder the empty state still renders the same greeting, so the page looks like Chat with two grey chips.
- The **Session pane** (Where, Model, Context and cost, Running programs, Connectors, Outputs) is thorough and plain. It opens **over** the chat at 1100 px (about 400 px wide), covering the right half of the composer (the model chip) and every header button, so a person cannot switch from Session to Terminal without first closing it. The six header panes are one-at-a-time and overlay; Claude's side panel pushes the chat narrower.
- Tab names in the pane (Terminal, Diff, Browser, File, Tasks) do not match the header button names (Changes, Files, Tasks and plan).

### Settings (in-app window, `index.html:428–460`; sections in `src/ui/settings.html`)
Pictures 07, 08, 09, 12.

- **The window is right:** fifteen entries grouped by a rule, a search box that filters the list, one section on screen. On a phone it is a list, then a page with a back arrow.
- **The standalone `settings.html` page is the opposite:** one scroll of 18 sections, 10,753 px tall at 1100 and 14,852 px at 390, with no in-page menu. It is still reachable (Automation links to it as "Settings", and it links to Providers), and a person who lands there thinks Settings is a manual.
- **Density:** most rows carry a paragraph. Examples: Brave Search key (about 900 characters including how the fallback chain works), Check Auto actions (about 600), Confine commands (about 500, with a "Not covered" list), Search this PC (a long paragraph plus two links). Claude's rows are one line and a control.
- **Splits and duplicates:** "Memory and instructions" (Settings) vs "Automation › Memory" vs the `/remember` command. "Skills" is a switch in Capabilities, a tab in Customize, and a form in Automation. "Connectors" is a switch in Capabilities, a tab in Customize, and "MCP servers" in Automation. "Providers and abilities" is a Settings entry that leaves the window for the Providers page. "Quick ask" has its own Settings entry, a Desktop-app block, and a note that the real switch is "in Bunny's own window".
- **Rows that read as internal:** Models › "Right now" shows Provider none, Model none, Test mode on (a test-profile switch, shown to every user in this build); "Allowed models" and "Aliases" are free-text boxes with one id per line; "Longest reply" and "Token budget for one reply" both limit reply size.
- **Permissions** is the heart of the product and the hardest to read: six paragraph rows, then rules written as patterns.

### Providers (`src/ui/providers.html`)
Picture 10.

- Connected providers first (good), then **Add a custom provider** as an open form, then "Available: on this PC" (Bunny local), then 25 popular providers in one list. The Anthropic card shows "key unverified" under a connected provider, with three models.
- For a first-time person the page has no recommendation. Claude has none of this, because Claude has no providers; Bunny must instead say "Start here".

### Quick ask (Settings; `electron/quick-ask.js`)
Not driven (global shortcut). The Settings text says it is a small bar, off by default, with "Change" for the shortcut. In Settings it appears in three places (own section, Desktop app, the Capabilities switch it links to). The note "Needs Bunny to keep running in the tray" is a second switch the person must find and turn on.

### Phone views (390 px)
Pictures 05, 06, 08.

- Chat is clean: title, composer, three chips. Drawer sidebar works. Settings as list then page is as good as the Claude app.
- Gaps: the model chip truncates ("Auto · Bunny Code (offli…"), the hint line is gone, header panes are reduced to two icons and a "⋯", and the Session pane takes the whole screen with no title context.

### Real window at 704 px (picture 11)
The sidebar collapses to a hamburger and the header drops to three icons plus "⋯". That is a sensible small-window layout. The window cannot go narrower, so the phone layout is only seen in a browser.

### Customize and Automation
Pictures not included (empty profile). **Customize** opens with two paragraphs of security explanation before the tabs (Connectors, Skills, Plugins; Yours / Discover). **Automation** is a long form page: Memory, MCP servers (remote + local), Schedules, Hooks, Skills. Each is an inline form with no examples. Claude has one "Connectors" place and one "Skills" place; Bunny has two of each.

## What "work on its own and smart" asks of the design

The owner's second sentence is about behaviour, not looks, but the screens decide whether a person trusts it. Three design needs follow from it, each already hinted at in the lists above:

1. **Say what it is allowed to do, in one place, before it starts** (improvement 1, simplification 1).
2. **Show what it is doing and let the person step in** (improvement 2, 7, 3).
3. **Pick the model for the job and say why** (improvement 4; the "Auto picked this for code: the best coding model available here" line already exists in the Session pane; it should be visible in the chip, not three clicks deep).
