## Findings

**P6-1, MEDIUM-HIGH (blocks).** `src/server/appTools.js:212` `add_skill` saves the model's text as a skill with `enabled: true`; `APP_TOOL_RISK.add_skill = 'edit'` (`appTools.js:11`), and `needsOk` (`app.js` ~1835) asks for `edit` only in Ask mode. So in Accept and Auto a model steered by a web page, a file or a connector's answer writes standing instructions that ride into every later chat, with no card. P-6 closed this for `install_plugin` and `add_connector` but not for the model's own skill; the HTTP route that does the same (`POST /api/skills`) is window-only for exactly this reason ("skills are instructions the model follows", `windowOnly.js`). Fix: `add_skill` arrives switched OFF in every mode, the same `switch_on_added` card shows the whole instructions (refuse over 1,800 characters so the card shows all of it, as W614-1), and only the window's yes switches it on. Test: Auto and Accept, a no keeps it off; a yes switches it on; over the limit is refused.

**P6-2, LOW.** `appTools.js` `pending` is one variable shared by every chat; another chat's app tool finishing between `run()` and `takePending()` can carry this chat's card into that chat. The card still describes what it switches on and still needs the window, so no bypass. Fix: return the pending item from `run()` (or key it by the call) instead of shared state.

**P6-3, LOW (wording).** The tool descriptions still say `install_plugin` "switches them on" and `add_connector` "switch it on" (`appTools.js:28`, `:32`); the results say OFF. Make the descriptions match, so the model does not tell the person the wrong thing.

**L5-1, LOW.** `PATCH /api/mcp/<id>` asks for `confirmLocal` when `command` or `args` change but not `cwd` (`app.js`, the L-5 block), and `mcpStore.update` drops `trustReadOnly` only for command/args. A changed working folder changes what a relative program or script runs. Fix: treat `cwd` like command and args. The route is window-only, so this is the window's own confirmation, not a bypass.

**L4-1, LOW (data, not exposure).** `mcpStore.update` with a secret store: for a connector whose migration failed earlier (plain values still in `env`), the last line deletes every remaining plain value although only the patched names were stored; the names stay, the values are lost (the connector starts without them). Fix: put each remaining plain value in the store (with read-back) before deleting it, or keep `env` for the names not stored.

**L3-1, LOW (note).** The hourly re-list (`relistReason` 'stale') takes a changed tool list silently, and `trustReadOnly` stays on for the connector's address. A trusted connector can later add a write tool labelled read-only. Acceptable with trust bound to the address; better: reset `trustReadOnly` when the re-listed set adds tool names, or show it in Customize.

## What holds

- **L-4**: values keyed `mcp-env.<id>.<name>` (DPAPI file name is a hash of the key); migration writes and reads back before the atomic rewrite, a failing store keeps the plain value; `view()` strips `env` from every answer (list, get, add, update, setStatus); names only in `mcp.json`; edit keeps unmentioned names and clears on blank; delete removes the secrets; the spawn reads values back through `withEnv`, and the same values feed `progressLine` masking and the exit text; the restart key is a sha256. Remote connectors store no headers (a plugin connector that needs headers or env is added off with no values), so requirement 7 has nothing to move.
- **P-6** for `install_plugin` and `add_connector` (remote): arrive off in every mode, card lists skills with instruction size and description, connector addresses, and skipped parts; Ask/Manual show the preview first; the answer route is window-only; a re-install is refused (`plugin.installed`); Customize install unchanged (tests). The preview reads the repository once and the install reads it again, but what is installed is off and the post-install card describes what was actually installed.
- **Batch-1 fixes (4f7339a)**: connector's own words as a fenced user-role message after the app's system text; only a clean "not supported" is cached; answers capped at about 5 MB.
- **P-5** plugin toggle `PATCH /api/plugins/<id>` is window-only (table and api.js copy, `window-only` 16/16).
- **H-1** a look-only helper gets connector tools only through `isReadOnlyTool` (trust set in the window).
- **L-5** the connector's own requests: ping and roots/list (empty roots) answered, the rest refused; no sampling or elicitation.
- **S-4** `useSkill` only names an enabled skill; the line put in front is fixed text plus that skill's name.
- **D-3** connector results over 8,000 characters are saved by the existing note writer: app-chosen name, `wx`, no links, inside the workspace, not in Plan, not incognito, not when `looksSecret`.
- **PV-2 fix** only changes what counts toward the 20,000-character limit; the not-offered check and permissions still apply to the real tool.
