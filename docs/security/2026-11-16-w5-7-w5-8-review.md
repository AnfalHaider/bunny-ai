## W5-8 @ 70bd964 — **PASS with conditions**

**What holds.** `release.mjs` fetches `origin main` first and refuses when the fetch fails, when `origin/main` is missing, when the target is not a commit (`--help`, `-x` and an empty target are all refused: no option injection), when the target is not exactly `origin/main` (a local commit not pushed, a branch ahead of main), and when a tracked file is edited. It passes the resolved full sha to `gh release create --target`, so the tag lands on that sha even if HEAD moves afterwards. `--target` and `--dry-run` are taken out of the arguments, so a second `--target` cannot override the first; `--dry-run` publishes nothing. The role and release-record checks before it are unchanged.

**Conditions (the check proves which commit is tagged, not which commit was built):**
- **W58-1 MEDIUM (verified on a throwaway repository).** The installer in `dist/` is whatever `npm run dist` last produced. The check passes while: (a) the tree is on another branch and the target is `origin/main` (`--target origin/main` from `claude/x` was ALLOWED), so the tag names main's commit and the installer is built from the branch; (b) an **untracked** file sits under a packaged folder (`src/untracked.js` was ALLOWED, because the dirty check is `status --untracked-files=no`), and it goes into the exe; (c) a stale `dist/` from an older build is there (ALLOWED; `dist` is ignored by git). Any of these publishes to every installed copy a program that is not the reviewed `origin/main`. Fix, in order: require `HEAD` to equal the target (the tree being built is the tree being tagged); drop `--untracked-files=no` (ignored files such as `dist` and `node_modules` still do not count); have `npm run dist` write the commit it built from (for example `dist/build-sha.txt` or into `package.json`'s extra metadata) and have `release.mjs` refuse when it is not the target.
- **W58-2 LOW.** Everything not `--target` or `--dry-run` goes to `gh release create` after the script's own flags, so `--repo other/repo`, `--draft`, `--prerelease`, `--latest=false` or a second `--title` are accepted. Only the Release Ops and Hotfix roles can run the script and the release record is required, so this is a slip, not an attack. Fix: pass on `--notes-file <file>` only.
- Role gate and release record are as before (the role comes from `BOOTSTRAP_ROLE` or the session file, so they stop mistakes, not a determined local program; the pre-push hook and `bootstrap` commands are the other layers).
