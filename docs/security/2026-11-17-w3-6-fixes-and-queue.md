## W3-6 with the fixes: **PASS at `3155e20`** (my conditions W36-1 and W36-2 are closed)
- **W36-1 closed (verified).** The token is saved with the origin it was issued for, and `authHeader` and `status` use it only when the connector's address has exactly that origin and is https (or this PC). Probe `docs/security/w3-6-probe/oa2.mjs` with a token for `https://c.example`: same origin, another path → sent; another host, the same host over http, another port, a subdomain, a look-alike host (`c.example.evil.example`), a userinfo trick (`c.example@evil.example`) and a token saved before the fix (no origin) → **nothing sent, shown as signed out**. Editing a connector's address (`PATCH /api/mcp/:id`, window-only) signs it out of the old place first (`signOutQuietly` on the old object, so the provider is told, and the stored token is removed).
- **W36-2 closed (verified).** A renewal in flight now re-reads the stored token after the provider answers and drops its own answer if the token is gone or changed; and `signOut` waits for a renewal in flight before it deletes. Probe: sign-out started 100 ms into a renewal, renewal released afterwards: the caller already waiting gets its answer, **the token is gone when both finish**, and the provider was asked to revoke twice (the new tokens, not only the old).
- **Also closed from my low notes:** W36-3 `100.64.0.0/10` and `.local` names are private addresses now; W36-4 one registered client per provider whatever the port (no new registration every launch).
- Builder A's tests: `mcp-oauth` and `mcp-signin-routes` 48 of 48 on my checkout.
- **For the merge into the v0.1.8 line:** keep `3155e20`, and make `appTools.uninstall` (W4-10) sign a connector out the way the delete route does (`signOutQuietly`), or the stored token stays behind when a plugin is uninstalled.
