## The gate's dependency audit (asked by the Chief of Staff for the owner)

The advisory: picomatch GHSA-fc5q-39xc-vjpf, a high-severity ReDoS with no patched version. It is reached only through the build tools (electron-builder → … → node-gyp → tinyglobby), and the patterns it matches are written by the project, not by an attacker. It is not in the installed app; the runtime dependency is `unpdf`.

My view: do not switch the gate to production-only as a blanket rule. The build tools make the installer every copy runs, so a high finding in them can matter, even though this one does not. Instead:
- keep `npm audit --audit-level=high` over everything;
- add an exceptions file, for example `docs/security/audit-exceptions.json`. Each entry gives the advisory id, the package path, why it does not reach the shipped app, who accepted it, and a review date at most 30 days ahead;
- the gate passes a high finding only when it is listed and not expired, and fails on any other.

Separately, run a `--omit=dev` audit at `moderate` for what ships.

This is a change to a security control in the gate, so it needs the owner's word.
