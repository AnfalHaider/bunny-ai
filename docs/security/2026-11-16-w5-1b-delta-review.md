## Evidence
- Builder's `test/guard-016-w5b.test.js`: 13 of 13 pass on my scratch checkout.
- Probe 4, same cases, `d3ee1cf` vs `611dee7`: 49 mismatches before, 44 after. Gone: `gh issue create`, `git push --repo=origin main`, a tag push by refspec, `git remote add`, `git remote set-url`. Nothing new appeared.
- **W5S-1 closed.** `--repo=origin main`, `--repo origin main`, `--rep=origin main`, `--repo=x main` are refused. Live-branch pushes in 26 other spellings are still refused (delete forms, `:main`, `HEAD:refs/heads/main`, a glob, `--atomic`, `--recurse-submodules=no`, quoted or split words, a variable).
- **W5S-2 closed.** For a builder these are refused: `gist create`, `repo create --public`, `repo fork`, `release create|upload|delete|edit`, `pr merge|close|edit|review|ready`, `issue create|edit|close`, `auth token|login|refresh|logout|setup-git|switch`, `extension install`, `alias set`, `config set`, `workflow run|enable`, `secret set`, `ssh-key add`, `api` with a method other than GET, `api graphql` with a mutation, `api` with `-f`/`-F`/`--input` on its own, `pr create` without a `claude/*` head (`--head main`, `-H main`, `-Hmain`, `--head=main`, a variable, an empty head, `origin:main`, `--base main --head main`). Wrapped forms are refused too: `GH_TOKEN=x gh …`, `& gh …`, `gh.exe …`, `gh "release" create`, a backtick inside the word, `-R x/y release create`. Reads stay allowed (`pr view|list|diff|checks`, `run view|list`, `issue view`, `release view|list`, `auth status`, `search`, GET `api`, `pr comment`, `pr create --head claude/x`).
- **G1-6 closed for:** `--tags`, `--follow-tags`, `--ta`, `refs/tags/…` on either side, `tag v1`, `:refs/tags/v1`, `refs/tags/*:refs/tags/*`, `--mirror`, `--all`, `refs/*:refs/*`; a web address, SSH address, folder, `file:///`, drive or UNC path as the push target (also after `--repo`); `git remote add` and `set-url` (also `--push`); `git config remote.X.url|pushurl` and `url.X.insteadOf`; `branch -f|-M|-m|-D|-d|-fD|--delete --force|--move|--forc` on the live name; `checkout -B`; `switch -C|--force-create`; `update-ref` and `update-ref -d`.
- A short tag name is looked up in the repo git runs in: with a repo that has tag `v0.1.5`, `origin v0.1.5`, `+v0.1.5`, `v0.1.5:claude/x`, `--repo=origin v0.1.5` and `V0.1.5` are refused. (In my probe repo, which has no tags, `git push origin v1` is allowed, as it should be.)
- `git checkout-index` with `--prefix`, `--all`, `-a`, `-fa`, `--stdin`, `--pre` (an abbreviation), and with `AGENTS.md` or `.bootstrap/policy.json` as a named file, is refused. `isRoleFile` and the real-hooks-path gate check: the tests pass; I did not probe them further.

## Still open (follow-ups; none makes the guard weaker than `d3ee1cf`)
- **W5B-1 MEDIUM-LOW, label move by a different case.** `git branch -f Main HEAD` is allowed (the live-branch name is compared case-sensitively). In a scratch repo on Windows it moved `main` (`main` then resolved to the new commit). The same comparison guards `-M`, `-m`, `-D`, `checkout -B` and `switch -C`, so `Main` goes around all of them. Fix: compare case-insensitively on Windows (and after stripping `refs/heads/`).
- **W5B-2 MEDIUM-LOW, `git symbolic-ref refs/heads/main refs/heads/claude/x` is allowed.** In a scratch repo with `main` checked out in another worktree it turned `main` into a symbolic ref to the other branch. Git's "branch used by worktree" protection does not cover it. `update-ref` is refused and this is the same move. Fix: refuse `symbolic-ref` on any `refs/heads/*` for roles that are not live pushers.
- **W5B-3 LOW, `git worktree add -B main <dir>`** is allowed. Git refuses it while `main` is checked out elsewhere, so it matters only when `main` is not checked out. Same fix as W5B-1.
- **W5B-4 LOW, `gh run download` and `gh release download` write wherever `-D`, `--dir`, `-O` or `--output` say**, and `download` is on the read list. A run's artifact comes from a workflow, and a role can push a workflow to its own `claude/*` branch, so this writes a file the write check never sees. Fix: refuse those options on `download`, or take it off the list.
- **W5B-5 LOW, tags and other ref namespaces are stopped by the shell layer only.** `probe6.mjs` on `611dee7`: the pre-push hook still allows `refs/tags/v9` for builder, security and qa (and any `refs/*` other than `refs/heads/<live>`). My W5-1 note said the pre-push hook was the backstop for tag pushes; that was wrong. A push made by a program that is not a Bash tool call (for example `node -e`) goes around the shell check. Fix: the pre-push hook refuses `refs/tags/*`, and ref names outside `refs/heads/claude/*` and `refs/heads/dev`, for roles that are not live pushers.
- Notes: `git push origin --delete v1` is allowed when `v1` is not a local tag; a deleted tag turns its GitHub Release into a draft and takes it out of the update feed, so it belongs with W5B-5. `git remote rename|remove|set-head|prune` are allowed (they do not change where a push goes). `gh pr create --head claude/x -R other/repo` and `--head fork:claude/x` pass the allowlist (a pull request in the wrong place; low). `git checkout-index -f ../x` writes outside the repository, which the write check does not look at (low). Builder's own leftover (a short tag name is looked up where git runs, not after a tracked `cd`) fails open only for that check.
