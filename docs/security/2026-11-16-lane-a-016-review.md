## What held

Refused: `..`, `../file`, absolute paths (both slash styles), drive-relative `C:x`, UNC, NUL byte, a junction inside the folder pointing out (as the start path). Include/exclude and find patterns that try to leave (`../*`, `../**`, an absolute path) match nothing. The walk uses `Dirent.isFile()/isDirectory()`, so a junction or symlink met *during* the walk is skipped, not followed (probe: whole-folder search and `**` find do not list or read the outside secret). This is stricter than before: the old search read through file links.
- **Data folder.** The tools add no new route to it: the folder gate (`folderToStore`, picker-only, `neverBrowse`) still decides what can be a workspace, and `inside()` blocks a link into it. Unchanged since D-2.
- **multi_edit (W2-3).** Risk is `edit` in `TOOL_RISK`, so Plan refuses it (by the risk) and Manual asks; Accept edits and Auto run it, exactly as for `write_file`/`edit_file` (the Chief's note says "asks in Manual and Accept edits": Accept edits does not ask for any edit tool, by design). The permission dialog's detail lists every pair (`app.js`, numbered `- old / + new`). All or nothing: a failing second edit leaves the file untouched and `beforeWrite` is not called; one `beforeWrite` call for the whole file (one undo). - **W4-1.** The port is `BUNNY_E2E_PORT` (an integer 1–65535) or a free one; the data folder is `tmpdir()/bunny-e2e-<port>`; the server is on `127.0.0.1`; reset only wipes that folder. No real-profile path in the changed e2e files.
- Brace expansion caps work: 256 expansions, 50 patterns, 300 characters.

## Findings

### LA-1 MEDIUM — the glob caps do not bound matching time (find_files, include, exclude)
`oneToRegExp` turns a glob into a backtracking regex. Twelve wildcards are allowed, which is enough for polynomial blow-up on a long file name: `*a*a*a*a*a*a*a*a*a*a*a*c` against a file named `aaa…ab.txt` took **2.6 s at 30 characters and did not finish in 60 s at 40** (`bt.mjs`). The pattern comes from the model and the file name from the workspace; `find_files` and `search_files` are `read` risk, so they run without asking in every mode that has a folder, Plan included. The tools run in the same process as the window, so the whole app freezes until it is killed.
**Fix.** Match globs with a linear matcher (the classic iterative wildcard match, segment by segment, no regex), or run the match under a time limit (see LA-2). Lowering MAX_STARS to 3 helps but does not remove the polynomial.

### LA-2 MEDIUM — a regex query can freeze the app; the line cap does not stop it
`search_files` with `regex: true` runs the model's pattern on lines up to 2,000 characters. `(a+)+$` against `aaaa…!`: **0.6 s at 22 characters, 9.7 s at 26, no result in 60 s at 30** (`r.mjs`). A 2,000-character cut allows far worse than that, and no RE2 is used. Same reach as LA-1: no approval, any mode with a folder (a prompt-injected file in the workspace can ask the model for the pattern; a hostile repo supplies the long line).
**Fix (cheap).** Test each file's lines inside `node:vm` with `timeout` (V8's watchdog does interrupt a running regex), or in a worker thread that is terminated after a few seconds, and return "stopped: the pattern took too long" for that file. A linear-time engine (RE2 compiled to WebAssembly) is the stronger fix. Do the same for the glob matcher so one wrapper covers both.

### LA-3 LOW — multi_edit with `replace_all` can grow a file until the process dies
50 edits of `a → aa` with `replace_all` on a 1,000-character file made a string of 262,144,000 characters and V8 aborted the process ("invalid size error", `m.mjs` last case): the app exits with no message. Reachable in Accept edits and Auto without a prompt; in Manual the person sees the pairs first. (`edit_file` with `replace_all` is one step, so far less reach.)
**Fix.** Refuse when the text would exceed a limit (say 20 MB, or 10 times the original size) before the replace, and check it again after each edit.

## Re-review of `9fb372f` — verdict **PASS** (one LOW follow-up)

Probes re-run on a scratch checkout of `9fb372f`: `p.mjs`, `m.mjs`, `bt.mjs`, plus new `r2.mjs` (glob and regex) and `r3.mjs` (many slow files).

- **LA-1 closed.** `glob.js` has no regexes now (two-pointer match per segment, a dynamic program for `**`). The 12-wildcard pattern that took 2.6 s at 30 characters and never finished at 40 now answers in 2 to 5 ms on 30, 40, 60, 200 and 250 characters; `*?*?…z`, a `**` chain, 256 brace expansions and the same pattern as a `search_files` include are all instant. `**/*.txt`, `sub/deep/**` and `ok.{txt,md}` still match what they should.
- **LA-2 closed for one file.** A regex search runs in a `vm` context with a 1 s limit per file: `(a+)+$`, `(a|aa)+$`, `(.*a){25}` and a lookahead variant over a 2,000-character line each stop at about 1.0 s with "That pattern is too slow; simplify it."; ordinary regexes (`hel+o`) answer in 7 ms; a literal query is escaped and never goes through the vm; an invalid pattern or code-shaped query is refused; the 500-character cap holds. The script text is fixed and the pattern only becomes a `RegExp` source, so the vm gives the pattern no way to run code.
- **LA-3 closed.** The doubling edit that aborted the process is refused ("would make g.txt about 33 MB, past the 20 MB limit"), and the file is unchanged.
- **Paths, data folder, multi_edit permissions, W4-1:** unchanged, probes still clean (no leak, junction skipped, edits all-or-nothing).

### LA-4 LOW (new): no total time budget for a regex search
The 1 s limit is per file, but the files are scanned 48 at a time with no pause between them (`search_files` batches, then `scan` runs synchronously). `r3.mjs`: 40 files each with one slow line (about 50 ms each) held the event loop for 2.05 s with **0 timer ticks**. A planted set of 48 files each tuned to just under 1 s would hold it for about 48 s per batch, and the first file that goes over the limit ends the search, so the attacker must tune both the files and the model's pattern. That is a far smaller hole than the original (which never returned), so I do not hold the PASS for it.
**Fix.** Give the whole search a budget (say 5 s of regex time in total, then "stopped: too slow, narrow the search") and yield (`await` a tick) between files.
