# S-OAUTH at f929949 (`claude/builder-b-soauth`): Security review: PASS

Closes open item 4 of my v0.1.8 log (OAuth discovery checked only the host name's text). The change is in `src/server/mcpOAuth.js` plus `test/mcp-oauth-private.test.js`.

## What holds

- **One path.** `request()` makes every OAuth call: discovery, registration, token, userinfo and revocation. Unless the host is a loopback name used over http (a local connector), it resolves the host (`all: true`). If any answer is private (`download.js` `isPrivateAddress`) the call is refused, and literal IPs are checked without a lookup. Then it connects to the first checked address.
- **The pinned connect defeats rebinding.** `pinnedFetch` gives node's http client a `lookup` that only ever returns the checked address. Probe (`pin.mjs` in my scratchpad), against a local server:
  - `http://rebind.invalid:<port>/x`, pinned to 127.0.0.1, answers `200 host=rebind.invalid:<port>`. A name that does not resolve still reaches the pinned address, so the name is never looked up a second time. The Host header keeps the name.
  - A 302 answer gives `redirect refused`.
  - `https://example.com/` pinned to example.com's own address gives `200`, so SNI and the certificate check use the name.
  - `https://example.com/` pinned to github.com's address gives `ERR_TLS_CERT_ALTNAME_INVALID`. The certificate check is not weakened by the pin.
- **Real names that resolve privately are refused** by the production engine (`discover({url})`, real DNS):
  - `localtest.me` (127.0.0.1): refused, `mcp.oauth.badUrl`.
  - `127.0.0.1.nip.io`: refused.
  - `10.0.0.1.nip.io`: refused.
  - `169.254.169.254.nip.io` (the cloud metadata address): refused.
- **The unchecked test path cannot be reached in production.** A test's own `fetchImpl` without a `lookupImpl` skips the check. In production the engine is built only in `connectorSignIn.js:28` as `createEngine({ secrets, redirectBase, ...engineOptions })`, and `app.js:255` passes no `engineOptions`. So `fetchImpl` and `lookupImpl` are null, and every call is checked and pinned.
- `localhost.` (trailing dot) is not in the loopback set, so it is resolved, and 127.0.0.1 is refused. The existing text checks (`notRemoteSafe` in `assertScope`) still stop a remote connector from pointing sign-in at a loopback name.

## Notes, not blocking

- The address check covers the OAuth calls only. The connector's own MCP requests (`mcp.js`) still go through plain `fetch` with the text checks.
