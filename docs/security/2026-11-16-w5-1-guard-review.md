## The three known gaps: acceptable to land
1. **A command word that is a variable (`G=gh; $G release create v9`) is not read.** Acceptable: it needs deliberate evasion, the same route `node -e` and a script already give (README: A2 is a seatbelt), and the real stop for publishing is not this guard but who holds the GitHub login. Cheap hardening (W5S-3): for a non-live role, refuse a command whose first word is dynamic when any later word is `release`, `merge` or `api`.
2. **The role file is a seatbelt, not proof.** Confirmed (probe 5): writing `chief-of-staff` into `<git dir>/bootstrap-role` makes the guard treat the session as Chief of Staff. The file tools and shell writes refuse that path; `node -e` does not. This is no weaker than `session.json` was, and it is now the first thing read, so keep it from being a step *down*: after landing, each worktree needs `bootstrap role <id>` once, because until then the environment variable and `session.json` still decide the role. The stronger design (W5S-4) is a role binding the person or Chief signs once and the hooks verify, not a file any shell can write.
3. **`gh` uses a denylist, not an allowlist.** Acceptable for landing but with a visible hole (W5S-2): `gh gist create [--public]`, `gh repo create --public`, `gh repo fork`, `gh pr review --approve`, `gh run rerun/cancel`, `gh codespace create`, `gh cache delete` are allowed. `gist` and `repo create --public` can put files outside the repo (for example the owner's real chats, which AGENTS.md says must never leave this machine) on the internet. An allowlist for non-live roles (read verbs, `pr create`, `pr view/list/checks/diff`, `issue` read, `api` GET) is the right end state.

## Follow-ups (file as board rows; Builder, then I re-check)
- **W5S-1 LOW** `git push --repo=origin main` (attached form) is allowed by the shell layer (`--repo origin main` and `origin main --repo=x` are refused). Fix: read `--repo=` as a repository option and judge the remaining words as refspecs.

- **W5S-3 LOW** dynamic command word with a publishing word after it (above).
- **W5S-4 LOW** the role binding (above).
- **W5S-5 LOW** deletion by wildcard or by the repo folder itself is not read: `rm -rf .`, `rm -rf *`, `rm -rf .g*`, `cd .. && rm -rf <repo>`, `find . -name .githooks -exec rm -rf {} +`, and mirror copies (`robocopy empty .githooks /MIR`). After any of these `core.hooksPath` points at nothing and no hook runs. Mitigated by the new gate check "git hooks wired" (it fails when the hooks folder is missing), so it is caught before a release, not before the next commit. Fix: refuse a recursive delete or `/MIR` whose target is `.`, a glob or a parent of the repo for non-chief roles.
- Not findings (seatbelt class, as the README says): config keys that run a program (`diff.external`, `filter.*.clean`, `gpg.program`, `sequence.editor`, `merge.tool`), `git rebase --exec`, `bisect run`, `push --receive-pack=…`, `git remote set-url/add`, `git symbolic-ref`, `git hook run`, tag pushes. All are routes `node -e` already gives; A1 at commit and the pre-push backstop are what stop their effect.
