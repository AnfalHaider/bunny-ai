## A. The three regressions the Chief confirmed (all verified in the code)
| # | 0.6.0 | Ours (G-1) | Effect |
|---|---|---|---|
| A1 | Push detection is `/\bgit\s+push\b/` on the whole command, and `pushTargets` splits on whitespace (`guard.mjs:23-45, 139`) | A tokenizer (`shellparse`/`shellrules`): quotes, `git -C x push`, `-c`, `--no-pager`, `git "push"`, env prefixes, `cmd /c`, `Start-Process`, aliases, `--repo=origin main`, bare URL targets | `git -C . push origin main`, `git "push" origin main`, `git --no-pager push origin HEAD:main` are not seen as pushes at all (the regex needs `git` + spaces + `push`); `--repo=origin main` makes `main` look like the remote, so no refspec is judged. For a non-live role the shell layer is then silent and only the pre-push hook stands |
| A2 | `matchesAny` is case-sensitive and `toRepoPath` is `relative()` with no canonical form (`policy.mjs:105-113`) | `toRepoPath` folds case, trailing dots and spaces, `::$DATA`, 8.3 names, `\\?\` and links to the real path (`isRoleFile`, `canonicalPath`) | `.BOOTSTRAP/policy.json`, `.Githooks/pre-push`, `agents.md`, `.bootstrap./policy.json`, `AGENTS.md::$DATA`, a junction into `.bootstrap` all miss `protected_globs` on Windows; the same trick on `DOCS/SIGNOFFS/x/QA.md` misses `recordRule`, so a role can write another role's sign-off |
| A3 | No `PLAIN_ID` check on the piece or role in `bootstrap signoff`, `approve`, `require`, `piece` (`bootstrap.mjs:240-275`: `join(root, 'docs','signoffs', piece, `${r}.md`)`) | Piece ids must be plain names | `bootstrap signoff ../../.bootstrap/roles --role builder --verdict PASS --note "…20 chars…"` writes `.bootstrap/roles/builder.md` with fixed frontmatter and **no `write_globs` and no `deny_commands`**, i.e. it rewrites the role's own brief and drops the brief's limits (any limits the flow itself sets for the role still apply: not checked); any `<role>.md` can be written anywhere in the repo or above it. By reading `signoff()`, not run. The command is on the settings allow list (no prompt), and the guard's CLI check only looks at the role, not the path (`guard.mjs:75-82`) |
