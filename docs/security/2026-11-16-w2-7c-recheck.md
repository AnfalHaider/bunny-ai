## Still open (follow-ups for Builder)
- **W27c-1 MEDIUM-LOW, the mode is still settable with only the token** (verified, `folderPickerOnly: true`):
  - `POST /api/sessions` with `permissionMode: "auto"` → 200, session is Auto.
  - `PATCH /api/sessions/:id` with `permissionMode: "auto"` → 200, now Auto (the `/setting/permissionMode` route is the only one blocked).
  - `POST /api/schedules` and `PATCH /api/schedules/:id` with `permissionMode: "auto"` → 200, an unattended Auto schedule.
  - And a prompt that asks the person is answered by `POST /api/sessions/:id/permission/:pid`, which takes the token alone.

  So today a token holder can make an Auto chat or schedule, or approve any Ask, without the window. Deny rules still hold in Auto (checked before the mode), so the protection W2-7 was built for stands. This is the wider **S-9 / W5-7** (what a token holder can do), and "the mode is window-only" is not true until these four are in `windowOnly.js`. Fix: put `permissionMode` in the body of session create/patch and schedule create/patch under the same check, and the permission-answer route too (the window answers its own prompts through `secure:write`).
- **W27c-2 LOW-MEDIUM, a quoted git word dodges a Deny** (verified with PowerShell's parser): with `git push*` denied, `git "push"` and `git p"ush"` are not stopped, though PowerShell runs `git push`. Names are normalised but arguments are not unquoted before the match. Same for `gh "release" create`. Fix: strip quotes and backticks from each word of the PowerShell reading before the pattern is matched, not only from the command name.
- **W27c-3 LOW, global options of `gh` and some of `git` are not skipped:** `gh -R x/y release create v1` and `gh --repo x/y release create` slip a `gh release*` Deny; `git --literal-pathspecs push` slips `git push*`. `git -c alias.p=push p` cannot be read at all. Fix: skip `-R/--repo` for `gh`, add `--literal-pathspecs`, `--glob-pathspecs`, `--noglob-pathspecs`, `--icase-pathspecs`, `--no-optional-locks`, `--bare`, `--namespace` for `git`; say in the Settings text that an alias cannot be matched.
- Not findings (the Settings text now says so): `[IO.File]::Delete`, `node -e`, `python -c`, scripts run by path.
