# How kit 0.6.0 with K-1 + K-2 was landed (piece kit-land)

**Landed on branch `claude/kit-land-k2` (piece `kit-land`), 2026-11-17; live in the main checkout only after the piece's sign-offs are complete and main is pushed.** How it was landed, from main 2400629 fast-forwarded to 1d3a77c:

1. `node scripts/kit-next/.bootstrap/bin/bootstrap.mjs upgrade`, run as chief-of-staff: it replaces `.bootstrap/bin`, adds `flow/`, `ui/` and `kit.json`, and keeps `policy.json`, `AGENTS.md` and our role briefs (the role briefs stay as the project edited them; this is intended).
2. `scripts/kit-next/.bootstrap/policy.json` copied over `.bootstrap/policy.json` (see "policy.json must change at landing too" below).
3. **`upgrade` skips files that already exist in `.githooks/`**, so the K-2 `pre-push` and `pre-commit` (the checks run from the main checkout) were copied from `scripts/kit-next/.githooks/` by hand. Without this step K-2's hook fix does not land. `commit-msg` was already identical.
4. `diff -rq` showed `.bootstrap/bin`, `.githooks` and `policy.json` equal to `scripts/kit-next/`.
5. `bootstrap kit apply` with the owner's words: record `docs/kit-changes/2026-11-17-kit-0.6.0.md`. Its hashes use the push check's `hashText` (line endings normalised, trailing whitespace trimmed), so they differ from a plain `sha256sum` of the file; checked 40 of 40 against the committed files with `hashText`. Run it with `CLAUDE_PROJECT_DIR` set to the landing folder, or it hashes the project's main checkout instead.
6. Not landed: the `.gitignore` line `.bootstrap/helpers/` (pre-commit refuses `.gitignore` for the Chief of Staff; a board row for the owning role).
