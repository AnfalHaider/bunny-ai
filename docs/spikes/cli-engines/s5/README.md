Files: `run.mjs` (driver, `run` and ACP modes), `stub.mjs` (stand-in OpenAI-compatible model that asks for scripted tool calls, logs every request, and a logging-only proxy that never forwards), `oc.mjs` (runs the binary with the fake home). `evidence/<scenario>.txt` is each run's output (the spike folder is shown as `<SPIKE>`).

## Verdict: NOT READY. Full mode needs two fixes, and neither is Bunny's to make by a flag
1. **Project plugins run code before any permission.** `.opencode/plugins/*.js` loaded despite the documented switches. The only workable handling found is to **run the engine in a staged copy that has no `.opencode/` folder** (and no `opencode.json`), which also removes any chance of a project plugin. Security must decide whether that is enough; it needs a test on the real adapter (a hostile `.opencode/` in the person's own folder must not reach the staged copy).
2. **Network beyond the model.** The engine downloads ripgrep from GitHub and installs its provider package from npm. To meet "no network but the model endpoint", Bunny must supply `rg` and pre-seed the provider package (or use a built-in provider shape), then show a clean capture. Not shown yet.
3. **Subagents are a hole in the approval channel.** Answer `task` with `reject` always; with that, the rest of the approval path held in this spike (every other tool reached the host first; the failure set is fail-closed; `always` is never sent).

If those are accepted, OpenCode can go to Security as a candidate for **full mode over ACP** (`once` or `reject` only). Restricted mode (no commands, web, subagents) still needs its own run.
