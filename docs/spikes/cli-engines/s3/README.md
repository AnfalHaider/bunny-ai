# Spike S3: Cline 3.0.74, run 2026-11-19 by Builder C

Nothing here is Bunny code. Files: `run.mjs` (driver: runs `cline.exe` headless against a stand-in model endpoint, or in ACP mode), `hook.js` (stand-in for Bunny's `PreToolUse` hook), `stub-chat.mjs` (stand-in OpenAI-compatible chat endpoint that asks for scripted tool calls and logs every request), `sanitize.py`, `evidence/<scenario>.txt` (command plus result of each run; the spike folder path shows as `<SPIKE>`), `evidence/tools-schema-first-request.json` (the tools Cline offers the model), `evidence/hook-payload-keys.json`.

## Set-up
- `npm install --ignore-scripts --save-exact cline@3.0.74` into the spike folder, with the npm cache inside it. 325 packages, every one with an `integrity` in the lockfile; 25,862 files, 312 MB.
- **The package has a `postinstall` script** (`node ./postinstall.mjs || true`). Read it (not run): it (1) renames a hub-discovery record `locks/hub/production.json` under the person's **own `~/.cline/data`** (or `CLINE_DATA_DIR`) when one exists ("shields" a running hub), and (2) hard-links the platform binary to `bin/.cline`. With `--ignore-scripts` neither happens; the `bin/cline` wrapper then finds the binary itself. Security should read it before Cline ships (CE-5.1).
- The real program is the compiled binary `@cline/cli-windows-x64/bin/cline.exe` (143,220,920 bytes, sha256 `fb1b3efa020f984235d38b64476ecbc7b3052a6a2e0f28797c147c28fb16b741`), a Bun executable; Authenticode **Valid**, signer `CN=Cline Bot Inc.`. **R4:** it runs on its own: a copy of the exe alone in another folder, with no Node on `PATH`, printed `3.0.74`. So no Node or Electron-as-Node is needed to run Cline; only the exe (143 MB) has to be pinned and shipped, not the 312 MB tree. (Node is needed only if the hook is a `.js` file, see below.)
- Each run: fresh project (`secret.txt`, `protected/`, a project `.cline/hooks/PreToolUse.js` that only records that it ran), a fake `USERPROFILE`/`HOME`/`APPDATA` with its own `.cline/hooks/PreToolUse.js`, `.claude` and `.codex` configs, `CLINE_DIR`, `CLINE_DATA_DIR` and `--config`/`--data-dir` set to an isolated folder, `..\outside\canary.txt`. Bunny's hook is `PreToolUse.js` in the isolated `CLINE_DIR\hooks`.
- **R3 (provider without signing in):** `cline auth openai-compatible -k <key> -m <model> -b http://127.0.0.1:<port>/v1 --config <iso> --data-dir <iso>\data` configures the provider offline (no network, no account): "Provider configured". It writes `data\settings\providers.json` **with the key in plain text** (`{"apiKey":"sk-fake","baseUrl":...,"tokenSource":"manual"}`). So the per-run endpoint token would sit in a file inside the isolated home (CE-4.3 allows that only where the CLI requires it; this CLI does, since the base URL has no command-line flag).
- The hook is a file named `PreToolUse` with one of the extensions `"", .sh, .bash, .zsh, .js, .mjs, .cjs, .ts, .py, .ps1`, found in `<CLINE_DIR>\hooks`, `<workspace>\.cline\hooks` and `<workspace>\.clinerules\hooks`; it receives the event as JSON on stdin and answers with JSON `{"cancel": true, "errorMessage": "..."}` on stdout (read from the bundled code). `--hooks-dir` adds a directory.

## Verdict: S3 FAILS for full mode; restricted mode is possible only with the canary question open (R24)
- Full mode is **not available**: with `--auto-approve false` the engine refuses everything a hook allows (no TTY, no ACP without an account), and with `--auto-approve true` the hook is the only wall and **fails open** (crash, kill, missing runtime, no hook) with no second layer, and the project's own hooks also run.
- Restricted mode (staged copy, commands off via `disabledTools`, Bunny reviewing the diff): the copy must leave out `.cline`, `.clinerules` and `.git` so no project hook loads. In it the hook still gates calls, but **the read path is open (R24)**: `read_files` can read a file outside the copy by absolute path, with the hook allowing or dead. Per the spec, the Chief of Staff goes back to the owner before Cline ships in restricted mode, and (CE-1) Cline is held to the same layers: no engine-side second layer exists, so Security's own rule says it "runs restricted" at most.
- Other facts for the adapter: the run result and every tool event stream as JSON lines in `--json` mode (`hook_event`, `agent_event`, `run_result`); a deny ends the run; the hook payload carries `preToolUse` and `tool_call` objects (`evidence/hook-payload-keys.json`); `data.cline.bot` is contacted regardless; the key goes into `providers.json` in plain text; the `postinstall` script touches `~/.cline/data` if the install is not run with `--ignore-scripts`.
- Not tested: a real model; `--yolo`; `-z/--zen` hub sessions; Cline's own MCP and plugin loading (`mcp`, `plugin` commands); whether a hook may return `review: true` to ask a person; interactive TUI approvals.
