Bunny local: run models on this PC

v0.1.16 · LOCAL-MODELS · from Tech Lead's spec (7898df8e) and Researcher's report (aace115b) · invented profile and PC only

For approval

In short

Today Bunny can talk to Ollama only if you install and run Ollama yourself and type its address. Proposed: one more provider, Bunny local, that needs no address, no key and no other program. You press one button to download a small program, pick a model from a short checked list, and chat. Bunny starts it when you ask and stops it when you stop asking.

  • Same pattern as the rest of Settings. A provider row, a card with rows and switches, and the engine rows' states (Not set up, Ready, Running). Nothing new to learn.
  • Every download says what it is (name, size, where from), checks a fingerprint, and can be paused, resumed, cancelled and deleted.
  • The fit badge is honest. Fits, Tight, Slow or Too big, worked out from this PC's memory before you download. Too big rows can't be downloaded.
  • Only the window manages it (Security LM-0). A phone or another PC, even one set to Everything, can chat with a model that's already downloaded; it cannot set up, download, add, start, stop or delete anything. Bunny itself has no tool for it either: it can suggest a model in words, and only you press Download.
  • Honest about trust (Security LM-1, 6, 7, 8, 11): the program is shown as unsigned, a model that isn't on Bunny's list gets a warning card whose main button is Don't add, and with a local chat model the Smart mode asks you instead of judging, unless you choose a checking model.
  • Models you already have (section 3c, added 2026-11-26): an "Add a model from this PC…" button for a .gguf file, and a "Found in LM Studio" list read from LM Studio's folder. Used in place, never copied or changed, with the same "Not on Bunny's list" warning and the same window-only rule.
Drawn with invented data. The PC is made up: 16 GB memory with 7.1 GB free, and a graphics card with 4 GB (3.6 GB free). Sizes are rounded and the model list is the spec's candidate list, which Security and the spikes may change. Folder names use the invented user Sam.

3 · The model list close up

Every state a row can be in, on this invented PC. Rows keep one shape: a name and a line of facts on the left, the one thing you can do on the right.

Rows

What each badge means

BadgeWhenWhat the row says
FitsNeeds less than 75% of free memoryFits on this PC. With a graphics card: Runs on your graphics card
TightNeeds 75% to 95%Fits, but close other apps first
SlowFits in memory only, while a graphics card is usedPartly on your graphics card: slower
Too bigAnything moreToo big for this PC. Download is off and there is no override

Memory needed = file size + room for the conversation + 1.5 GB. The check runs again before each start, so a PC with less free memory today can turn a Fits into a Tight. A model also says "Uses tools" or "Chat only"; below 16k of room it is chat only on this PC, and the row says why.

Download checks, in order
  1. Enough room: file size + 2 GB free on the data folder's drive, or nothing starts.
  2. Hugging Face still offers the exact file Bunny was updated for (size and fingerprint). If not: "This model changed on Hugging Face".
  3. While downloading, the fingerprint is computed. At the end it must match. If not, the file is deleted.
  4. Before every start Bunny checks the files again.

3b · A model that isn't on Bunny's list

Bunny's own list is checked by Security for publisher, licence and chat template; anything else is on you, and the card says so before anything downloads. The spec leaves "Add from a Hugging Face link" for later, so this is drawn for the day it is built.

The warning card

Two ways it stops

There is no Hugging Face login in Bunny. A gated model is refused in one sentence. Only .gguf model files are ever downloaded: nothing else from the repository.

3c · Models already on this PC

Added after the owner's word (plan 28d7a432): "Add a model from this PC" picks a .gguf file, and "Found in LM Studio" lists what is in LM Studio's models folder. Same card, same row shape, below Bunny's own list. Nothing else on the PC is searched, and Ollama is not in this release. Wording follows Security's LF-1 to LF-12 (3ef005c2).

The card, below the list (Ready)

Two groups under the models Bunny downloads. Your own files are used where they are: Bunny never copies, moves, edits or deletes them. The only thing "Remove from list" does is forget the entry.

A narrow window, same card

Adding one: the warning card

Two cards, one per kind: an LM Studio entry (top) and a file you picked (bottom, with an unknown chat format shown in a view you can open). Bunny reads the header and the template first, so the card has real facts, and checks the file again before every start. The main button is Don't add; Add is second. Tools stay off until you turn on "Use tools with this model" for it, in the window (LF-5). Security LF-1 to LF-12.

Seven ways a file is refused

All stop before anything is added, and the file isn't touched. An unknown chat format isn't a refusal: it is shown on the add card and you decide. A file with no chat format runs as ChatML, with tools off. Too big for memory isn't a refusal either (LF-3): the add card says "This may not fit in memory and can make the PC slow" and shows free memory. Only a template that is too large or unreadable is refused.

A file that was there and now isn't

Checked when the card opens and again before every start. The entry stays so you can point it at the new place; nothing is deleted. A file that is there but different from when you added it is refused the same way the program is (section 6).

LM Studio isn't installed

Not an error: one calm row, and the way out. Bunny only reads LM Studio's folder to list model files. It doesn't start LM Studio, read its settings or chats, or look anywhere else.

In the chat's model menu

A file you added sits in the same group, tagged Your file, so it is never mistaken for one Bunny checked.

Words and decisions

Names: the button is "Add a model from this PC…". The group is "Found in LM Studio". LM Studio's folder is shown by path so you can see what is read. Files that aren't chat models (vision helper parts, split pieces) are counted in one line, not listed.
Settled by Security: files are used in place (LF-7); an unknown chat format is shown and you decide (LF-4, LF-6); the real file name and folder show in this window only, never on a phone or device or anywhere the AI can see it, because the path holds the Windows user name (LF-1, LF-2). The paths drawn here are invented.

A · Where Bunny saves what it downloads

The row: default, then after a change

One place for what Bunny downloads: the models. (The runtime program stays in Bunny's own folder, because Bunny checks it before every start.) The default is Bunny's own folder. Change… opens Windows' own folder picker; nothing is typed in. Bunny saves only into a folder it creates inside your pick, named Bunny models. Each model's own folder shows in this window, so models in two places are never a surprise.

After picking a folder

Move is offered first and recommended (Security LF-21). If models stay behind they sit in two places, "Remove Bunny local" has two places to clean, and nobody can tell which is current. Leave is the other answer: old models keep working from where they are, and only new downloads go to the new folder. Refused while a download is running.

Moving

For each model, in order: the old copy is checked against its fingerprint (if it changed, it isn't moved and says "This file changed after Bunny downloaded it"); room is checked for the whole move first; the copy is checked in full against Bunny's pinned fingerprint before it gets its final name; only then is the old file deleted. Cancel or a failure keeps every model not yet moved on its old copy.

A folder Bunny won't use for downloads

Security's wording (LF-14, LF-15, LF-19, LF-22, LF-23). A removable drive is refused for downloads (a model folder on one is fine, in B). Project folders, Downloads and Desktop are refused so nothing that writes files can swap a model. OneDrive and Documents are fine.

The folder is gone later (drive unplugged, folder renamed), and a file that changed

Found when the card opens and before every start. Models aren't deleted or forgotten, and nothing is downloaded again on its own: they show Not found and come back when the folder does. There is no automatic fall back to Bunny's own folder.

Words and decisions

Settled by Security (LF-13 to LF-26): window only, folder from Windows' picker, never shown to a phone or device or the AI; real path stored and shown; a link as the download folder itself refused; never a system, program, data or drive-root folder, or a folder that contains a project folder; no overlap with a model folder; Remove Bunny local deletes only recorded downloads that still match. The five choices in this section were accepted: Move recommended, removable refused for downloads and allowed in the list, no project, Downloads or Desktop folders, Remove deleting only what Bunny recorded, three levels deep.

B · Folders Bunny lists models from

The card

You add folders; Bunny lists the .gguf files in each one and the folders inside it (three levels deep, which fits LM Studio's own layout; up to 5,000 entries; links aren't followed; a file two folders reach is listed once). LM Studio's folder is found automatically and listed first, tagged Found automatically; if you remove it, it stays removed until you add it back. Up to 20 folders. Files are read where they are, never copied or changed. Adding one from a list still goes through the add card in 3c.

A narrow window, same card

A folder that is missing, empty, or on a removable or network drive

Adding and removing a folder

Remove says what it does and doesn't: your files and anything you downloaded elsewhere aren't touched. Models you added from that folder stop being listed (and stop being chosen in the chat) until you add the folder again.

5 · Loading, running and stopping

First message after a start

Starting can take up to two minutes on a slow PC. The line stays until the first words arrive, then goes away. Quick ask shows the same text in its bar: "Starting your local model…".

Settings: the idle stop and Stop now

Default is 10 minutes with no request. Stopping waits for a reply that is still arriving. Quitting Bunny always stops it.

6 · When something goes wrong

Plain words, one next step each, never raw program output. The first three show in the chat; the rest in the card.

Not enough memory (in the chat)

The program is missing (in the chat)

The program changed on disk (in the chat and the card)

A download didn't match its fingerprint (in the card)

The model changed on Hugging Face (in the card)

Not enough disk space (in the card)

7 · Removing Bunny local

Two clicks, and the second names the size. Remove Bunny local deletes the program, the models, the cache and the key file. Because the models are the big part, a second confirmation says how much disk comes back and that models are removed too. Delete on one model asks nothing: it is only a download and can be fetched again.
On a phone or another PC (both device levels, Everything included) there is no Set up, Download, Add, Start, Stop now, Delete or graphics switch, and a device is refused if it tries. The Bunny local card isn't drawn there; the model menu and the loading line are the only parts a device sees. A device set to Everything still isn't "the window" for this.

For the Chief of Staff, Tech Lead and Security

  • Words I chose that the spec doesn't fix: "Set up" (the program), "Download" (a model), "Stop after idle", "Use graphics card", "Runs on: graphics card / CPU". The CPU/Vulkan choice is not asked: Bunny picks, and the person only has the Use graphics card switch (spec LM-5b).
  • Fingerprint on screen: the card says "Checked" with a short fingerprint (first 12 characters) in a details line, so a person can compare it with Hugging Face. The full value stays in the program's own list.
  • Disk location: shown as a path with a Show in folder button, window only. It is inside Bunny's data folder, which Bunny's own tools can't write to.
  • Words that depend on spikes (Security says so): "This program isn't signed" (LM-1, only if the binaries really are unsigned), a SmartScreen warning line, and the fallback "the model runner runs with your rights; a crafted model file could act as you" if the low-rights run doesn't work (LM-3). The unsigned line is drawn; the other two I add the day a spike says they are true.
  • Settled: Remove Bunny local deletes the program and the models Bunny recorded as its downloads, wherever they are, naming each place and the size; only files that still match their record are deleted (Security LF-24). "Slow" allows Download; Too big does not.
