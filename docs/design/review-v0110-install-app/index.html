Bunny as an installed app

Design drawing for the owner's approval. Nothing visible is built until you approve it. The plumbing (icons, a versioned cache, links to the manifest) is being built separately because nothing in it can be seen. Names, addresses and times in the pictures are examples.

v0.1.11Risk: MEDIUM (a service worker can serve an old page; no security control changes)Light and dark; desktop and phoneDesign session, 2026-11-18
The owner's words
"Also ensure that accessing the application through web, it becomes a web app."
What is proposed, in one paragraph
When Bunny is opened in a browser on this computer (http://127.0.0.1:<port>), the browser can install it as an app: its own window with no address bar, its own icon in the Start menu and taskbar. Bunny gets an Install as an app row in Settings that does it with one button, and says plainly when it cannot. The installed window looks like Bunny, not like a browser: a calm title bar in the app's own colours, and on a phone the page fills the screen behind the notch and the home bar while the text stays clear of them. On other devices over the network, browsers allow only a home-screen shortcut (a link that opens in a browser tab), because a full install needs HTTPS, which Bunny does not have on the network. That is shown as a decision at the bottom, not built.

1. Settings → Use Bunny in a browser → "Install as an app"

The Install button can only work from a browser tab (the browser decides whether to offer it), so the row lives on the Settings page as the browser shows it. In Bunny's own window the same group only gets a pointer line under "Open in your browser". The network line is always there, so nobody expects an install on a phone that the browser will not allow.

2. The installed window on this computer

Today the manifest asks for a violet title bar (theme_color #6a4fd8) while the page itself is warm white or near-black, so the window has a loud violet strip above a calm app. The proposal makes the title bar the app's own background in each theme, with a hairline under it, so it looks like part of Bunny. Everything below the title bar is the normal app.

3. The installed app on a phone: notch and home bar

Today the page does not ask to fill the screen behind the system areas, so the phone shows its own strips above the header and under the composer, in a different colour. The proposal asks for the whole screen (viewport-fit=cover) and keeps text clear of the notch and the home bar with the safe-area insets: the header grows by the top inset, the composer sits above the bottom inset. The dashed lines mark those insets (the sizes are examples; each phone reports its own).

4. A phone on the network (plain HTTP): a shortcut, not an install

Over http://192.168.x.x a browser offers only "Add to Home Screen", which makes an icon that opens Bunny in a normal browser tab, with the address bar and a "Not secure" mark. It works, and the sign-in and window-only rules are the same, but it is not an installed app. A full install on a phone needs HTTPS (decision 2).

Risk: MEDIUM

  • Stale page after an update is the real risk: a service worker that keeps an old shell shows the old Bunny against a new server. The versioned cache and the "Update ready" bar are part of the design, not extras, and need a test that an update replaces the cache.
  • No private data in the cache: only the app shell (pages, styles, scripts, icons). Never /api/, chats, files, or the sign-in cookie's pages. The service worker must not be used on the other-device address (it cannot run there anyway: not a secure context).
  • No change to any security control: the S-1 guard, the window-only rules and the sign-in are untouched. Installing does not give an installed window more rights than a tab on 127.0.0.1.
  • The title bar and the safe-area work are visual and need the walk on a real phone (notch and home bar) and in a real installed window, which a desktop browser cannot show.

Decisions for the owner (my recommendation first)

  1. Install on this computer from 127.0.0.1: yes (recommended, decided). One button in Settings, its own window.
  2. Install on a phone over the network: not now (recommended). It needs HTTPS (a certificate the phone trusts, or a tunnel), which is more setup and a Security review; for now a phone gets the home-screen shortcut and the same sign-in. It can be its own step later.
  3. Title bar colour. The app's own background in each theme (recommended), or keep the violet from the manifest.
  4. Where the Install button lives. In Settings, on the page as the browser shows it, with a pointer line in Bunny's window (recommended); or also a banner in the browser tab offering to install.
  5. Updates. A new version waits and shows "Update ready · Reload" (recommended), or applies silently the next time the app opens.

Not drawn: the browser's own install dialog and address-bar icon (the browser draws them), and how to remove the installed app (the browser's own menu: Apps, then Uninstall).
