What is proposed, in one paragraph
Two steps, and the second is off until the person turns it on. 1. Open in your browser: a button in Settings (Desktop app) and an item in the tray menu open Bunny in the default browser at an address on this PC only (127.0.0.1), next to the desktop window. The window-only controls (permission mode and rules, connectors, installs, updates) are locked in the browser and say "Change this in Bunny's window." 2. Allow other devices to open Bunny: a setting, off by default, that lets a phone or another computer on the same network open the same address after a plain warning, a passcode the person sets, and the Windows firewall question. Other devices sign in with the passcode, and every window-only control stays locked for them too. The owner has decided: local network only. Reaching Bunny from the internet is not drawn; it is a note for later (it needs HTTPS).

1. Where the option lives: today and proposed

The desktop-only settings are in Settings → Desktop app (there is no "General" page in Bunny; Desktop app is where the startup, tray and Quick ask items already are). The tray menu gets one item. Nothing changes for a person who never uses it.

2. Turning on "Allow other devices to open Bunny" HIGH

Four things happen in this order, each one a screen the person sees. Off is the default and is also what Bunny returns to after every restart (decision 3).

3. On the other device

A phone or another computer opens the address, sees a sign-in page, enters the passcode, and gets a session cookie (HttpOnly, SameSite=Strict). After five wrong tries in a row that device waits before it can try again. Once in, it sees Bunny with the window-only controls locked.

4. The browser view: the composer and Settings

The browser shows the same Bunny. What differs: controls that change what Bunny may do or run are locked and say where to change them. They are the same ones the server already refuses outside the window (the window-only list), so the browser cannot unlock them. A phone gets the same page at phone width.

5. In Bunny's window while it is open to other devices

A line across the top of the window, in the warning colour, for as long as the setting is on. It cannot be missed and it has the off switch.

Risk: HIGH, and why

Security reviews this before any build. Today the server can be reached only from this PC and only by pages that carry its token. Step 1 keeps that and only opens a browser at it. Step 2 is the part that changes the exposure: the server would answer other devices, so it needs a sign-in of its own in front of everything.

Security's conditions for step 1 (this PC only)

  • 127.0.0.1 only. The setting "Allow other devices" is off, and the server does not listen on any other address.
  • The S-1 guard is unchanged. No token in the URL, in a bookmark, in history or in anything the person can copy.
  • Window-only stays window-only. The browser shows those controls locked: "Change this in Bunny's window."
  • Artifacts stay sandboxed in the browser.

Added conditions for step 2 (other devices), for Security to confirm or change

  • Off by default, and off again after every restart. Turning it on needs the plain warning and a passcode the person sets (12 characters or more, or one Bunny generates and shows once).
  • Sign-in before anything: a device that has not signed in gets only the sign-in page. Session cookie: HttpOnly, SameSite=Strict. After 5 failed tries in a row that device waits (the wait grows); the failures are counted per device and in total.
  • The passcode is stored hashed on this computer and never shown again; the generated one is shown once with a copy button.
  • Every window-only control is locked for a remote device, and so are terminal, computer use and installs; the remote device can chat, read chats and files the chat already shows, nothing that runs something new on the PC without the window (to be confirmed by Security, listed in the decisions).
  • Signed-in devices list with a Sign out for each and a "Sign out all". Turning the setting off ends every session at once.
  • Local network only (decided by the owner). The address is the PC's LAN address. The server refuses a request whose address or Host header is not one of the PC's own addresses, so it is not usable through a forwarded port by accident.
  • Not the internet. Nothing here is meant to be reached from outside the home network. Do not forward a router port to it.
  • The Windows firewall: the first time Bunny listens on the network, Windows asks. Bunny tells the person what to expect before it happens, and recommends Private networks only (the dialog below).

Behaviour

  • Bunny must be running. The browser talks to Bunny on this PC; if the window is closed and Bunny is not kept in the tray, the browser page says "Bunny is not running" (drawn in section 4). With "Keep running in the tray" on, Bunny stays available.
  • Same address after restart (recommended, off by default): Bunny uses a fixed port so a bookmark keeps working. If the port is taken by another program, Bunny says so in Settings and uses a free one.
  • Status line in the window whenever other devices are allowed: "Open to other devices · N signed in · Turn off".
  • The launch flag is out (the owner's clarification): the browser is reached by the button and the tray item only.

Decisions for the owner (my recommendation first)

  1. Local network only: decided. The owner chose local network only. Reaching it over the internet is for later and needs HTTPS (a tunnel or a certificate); it is not drawn.
  2. Passcode, or approval from Bunny's window. A passcode (recommended: it works when the person is away from the PC), with a second option later where each new device waits for a click in the window.
  3. Does it stay on after a restart? "Allow other devices" turns off at every restart (recommended); "Keep the same address" stays as set.
  4. Bunny must stay open. Closing the window ends the browser session unless Bunny keeps running in the tray. Recommended: say so in the setting and offer "Keep running in the tray" next to it, as drawn.
  5. Button, launch flag or both. Button and tray item only (the owner has ruled the flag out).
  6. What a remote device may do. Chat and read only what chats show; everything that runs on the PC stays in the window (recommended), or also allow files and tools later by decision.

Not drawn: the sign-in page's "forgot the passcode" path (the person sets a new one in the window, which ends every session), and the exact Windows firewall wording, which is Windows' own and may differ by version.
